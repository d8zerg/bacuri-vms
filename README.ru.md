# ![Знак Bacuri](design/bacuri/brand/icon-48.png) Bacuri VMS

[English version](README.md)

**Открытая система видеонаблюдения для автономной работы на объекте.**

Bacuri VMS записывает камеры на собственных серверах площадки, показывает эфир и архив в браузере и работает без доступа в интернет и облачных сервисов. Оператор находит камеру на плане здания, переходит от тревоги к нужному кадру и сохраняет эпизод как подписанное доказательство. Администратор подключает камеры, назначает запись и выдаёт доступ ровно к тем точкам, которые нужны сотруднику.

Проект распространяется как свободное ПО по [лицензии MIT](LICENSE): без лицензий на камеру, без зависимости от облака и без привязки к производителю камер.

## Принципы

| Принцип | Что это значит на практике |
| --- | --- |
| Открытость | Публичные контракты REST, WebSocket и gRPC, документированный формат архива и экспорта, каталог ошибок с устойчивыми кодами, отсутствие привязки к поставщику |
| Скорость оператора | Эфир, лента тревог и архив в одном действии друг от друга, работа с клавиатуры, у каждого состояния видна причина |
| Правдивость архива | Шкала архива разделяет запись, пропуск, оценочное время и каталогизацию. Экспорт подписан и проверяется на машине без системы |
| Автономность | Площадка владеет камерами, данными, правами и восстановлением. Локальный вход и запись работают при недоступности внешних сервисов |

## Возможности

- **Камеры.** Обнаружение по ONVIF, в том числе адресное обнаружение за маршрутизатором, подключение по RTSP, пакетная настройка каналов по шаблону площадки с ревизиями и откатом, замена камеры с сохранением архива точки.
- **Эфир и управление.** Эфир по WebRTC с фактическим профилем, кодеком и разрешением каждой ячейки. Поворот, наклон, зум, фокус, предустановки, патрули, подсветка, стеклоочиститель, реле и входы камеры в пределах возможностей ONVIF. Отдельные права на прослушивание, запись звука и передачу речи.
- **Запись и хранение.** Непрерывная запись, запись по расписанию, по событию и вручную с интервалами до и после события для камер и групп. H.264 и HEVC Main записываются без перекодирования. Срок хранения, резерв тома, проверяемая вторая копия архива и догрузка пропусков из памяти камеры.
- **Тревоги.** Живая лента с возобновлением после разрыва, обработка с одним владельцем тревоги, ограниченное поручение, журнал, видеоправила с зонами, линиями и расписаниями с проверкой на записи до включения.
- **Расследования.** Поиск движения в области кадра и по событиям, синхронный просмотр четырёх камер, закладки, дела с удержаниями, которые защищают интервалы от очистки, экспорт оригинала или производной с масками и автономной проверкой подписи.
- **Карты и планы.** Карты регионов без внешней сети, планы этажей с геопривязкой, размещение камер и откалиброванные секторы обзора.
- **Доступ.** Локальные учётные записи, вход администратора с ключом WebAuthn, необязательный корпоративный вход через OpenID Connect, группы точек, маски приватности и журнал доступа.
- **Рабочее место.** Один веб-клиент для операторов и администраторов со светлой и тёмной темами и интерфейсом на английском и русском.

## Архитектура

Площадка работает с модульным ядром управления и отдельными процессами записи, выдачи видео и приёма наблюдений. Процессы используют общие контракты и размещаются на одном узле или распределяются по кластеру.

| Компонент | Технология | Ответственность |
| --- | --- | --- |
| Ядро управления | C++23, Boost.Asio и Boost.Beast, PostgreSQL | Каталог ресурсов, права, политики, тревоги, REST API и лента WebSocket |
| Узел записи | C++23, GStreamer, журнал SQLite | Приём потоков и архив на локальном томе независимо от ядра |
| Выдача медиа | C++23, GStreamer WebRTC | Эфир и воспроизведение архива в пределах разрешения ядра |
| Источник наблюдений | C++23, gRPC | Движение и события камер для ядра |
| Веб-клиент | TypeScript, React, Vite, MapLibre GL JS | Рабочее место оператора и администратора |

Внутри площадки службы взаимодействуют по gRPC. Клиенты используют публичный HTTPS API. [Архитектура](docs/ru/architecture.md) · [Доменная модель](docs/ru/domain-model.md) · [Формат архива и экспорта](docs/ru/archive-format.md) · [Архитектурные решения](docs/ru/adr/)

Подписанный автономный комплект устанавливает систему на Debian Bookworm или Trixie для amd64. Узлу не нужен сетевой репозиторий: PostgreSQL и все компоненты входят в комплект.

## Разработка

Для разработки нужны Linux x86-64, нативный Docker Engine с плагином Compose и [Go Task](https://taskfile.dev/docs/installation/). Все сборки и проверки выполняются в контейнерах.

```sh
task stand:up       # PostgreSQL и синтетическая RTSP-камера
task control:up     # ядро, узел записи и выдача медиа с применёнными миграциями
task test           # сборка и запуск тестов C++
task check          # полная проверка качества: сборки, санитайзеры, статический анализ, контракты и сценарии стенда
```

Каждый продуктовый модуль сохраняет покрытие строк не ниже 75%, контракты, ссылки документации и каталог ошибок проверяются автоматически. [Локальный стенд и команды](docs/ru/local-development.md) · [Качество кода](docs/ru/quality.md) · [Профиль испытаний](docs/ru/test-profile.md)

## В разработке

- **Настольное рабочее место.** Клиент на Qt для многомониторных постов, видеостены, физического пульта PTZ и автономной проверки экспорта. [Макеты экранов](docs/ru/desktop-ui.md)
- **Серверная видеоаналитика.** Отдельный сервис на OpenCV для сопровождения объектов, линий и зон, контроля саботажа камер и автоматического обезличивания экспорта. [ADR-021](docs/ru/adr/021-video-analytics.md)
- **Bacuri Manager.** Управление несколькими площадками с общими политиками и поиском. [Федерация](docs/ru/architecture.md#8-федерация-и-внешние-интеграции)
