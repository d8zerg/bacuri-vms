# Обновление и восстановление Bacuri VMS

Профиль охватывает Debian 13 amd64, обновление с 0.1.0-1 (схема 14), 0.1.1-1 (схема 15), 0.1.2-1 (схема 16), 0.1.3-1 (схема 17), 0.1.4-1 (схема 18), 0.1.5-1 (схема 19) или 0.1.6-1 (схема 20) до 0.1.7-1 (схема 21) и возврат к сохранённой версии. Испытательные пакеты имеют суффикс `~qualification`. Сохраните оба подписанных комплекта и независимо доверенные ключи. Команды выполняются в локальной консоли root. Стенд проверяет возврат на независимо подготовленный Debian с установленными пакетами и доступными средствами восстановления. Для работы `bacuri-maintain` на чистом узле сначала установите зависимости штатным установщиком комплекта.

Миграция 18 добавляет калибровку направления и последнее измерение PTZ. Миграция 19 добавляет опциональную геопривязку планов и источник геопозиции точки. Миграция 20 строит индексы очереди карт и размещений камер и обновляет чтение таймлайна. Индексы строятся в транзакции при остановленных службах. Длительность окна обслуживания зависит от объёма этих таблиц. Миграция 21 добавляет настройки OIDC и области доступа. Она сохраняет действующие назначения просмотра, PTZ и экспорта. Для перехода на 0.1.7 используйте средство обслуживания из нового подписанного комплекта и сохраните комплект исходной версии для отката. Миграция 16 перемещает таблицы и функции между схемами в одной транзакции. Миграция 17 сохраняет исходный регион и его тайлы, добавляет идентификаторы регионов и очередь установки карт. После обновления версию показывает запрос `SELECT max(version) FROM bacuri_meta.schema_migrations`. На схемах 14 и 15 журнал находится в `bacuri_inventory.schema_migrations`.

## Копия и обновление

Предоставьте новый путь для снимка на независимом носителе с доступом только у root. Создайте отдельный 32-байтовый ключ восстановления с правами 0600 и храните резервную копию этого ключа отдельно. Один снимок включает логический дамп PostgreSQL с правами, историей и каталогом, параметры служб, идентификаторы, ключи площадки и сертификаты. Файл зашифрован и аутентифицирован. Видеоблоки и журнал тома храните на отдельном архивном носителе. Индекс локальных назначений рекордера восстанавливается из PostgreSQL. Во время обслуживания `/var/tmp` содержит закрытые для других пользователей временные файлы с открытыми данными. Используйте защищённый системный диск.

```sh
set -eu
umask 077
# Для нового хранилища ключей выберите новый файл.
( set -C; openssl rand 32 > "$key" )
gpgv --keyring "$new_trust" "$new_kit/bacuri-maintain.sig" "$new_kit/bacuri-maintain"
"$new_kit/bacuri-maintain" backup "$online_snapshot" "$key"
"$new_kit/bacuri-maintain" upgrade "$new_trust" "$new_kit" "$upgrade_snapshot" "$key"
```

Периодические копии можно получать на работающем узле. Для целевой RPO прав и конфигурации интервал между успешными снимками должен укладываться в пять минут. Обновление проверяет подпись комплекта и место для снимка, останавливает службы, сохраняет отдельную копию до миграции и запускает службы после её завершения. При прерывании повторите команду с теми же путями. Маркер `/var/lib/bacuri-maintenance/pending` сохраняет запрет запуска служб после перезагрузки.

## Откат и восстановление

Для отката используйте средство обслуживания из нового комплекта, доверенный ключ и пакет версии, указанной в снимке.

```sh
"$new_kit/bacuri-maintain" rollback "$old_trust" "$old_kit" "$upgrade_snapshot" "$key"
```

Команда возвращает конфигурацию, права и историю к моменту копирования. Проверьте изменения прав, выполненные после снимка. Сохранившиеся завершённые блоки того же узла проходят сверку с каталогом.

Для восстановления на чистом узле установите пакет версии снимка без первичной настройки, подключите сохранённый ext4-том в `/srv/bacuri-archive` и верните его запись в fstab. Убедитесь, что в целевой PostgreSQL нет действующей площадки. Передайте комплект той же версии, что и копия.

```sh
"$new_kit/bacuri-maintain" restore "$trust" "$kit" "$snapshot" "$key"
```

При восстановлении прежние браузерные сессии закрываются и привязки WebAuthn сбрасываются. Администратор входит с исходным паролем и заново регистрирует ключ по одноразовому коду локальной консоли. Начиная с 0.1.1 для утраченного ключа действующей площадки выполните `bacuri-vms admin recover-admin ИМЯ`. Команда отзывает привязку и активные сессии этой учётной записи и выдаёт код на десять минут. После восстановления используйте `bacuri-vms admin enroll-admin ИМЯ`. Начиная с 0.1.2 журнал действий доступен в `bacuri_access.credential_audit`, в 0.1.1 - в `bacuri_inventory.credential_audit`.

## Диагностика

`bacuri-maintain diagnose НОВЫЙ_КАТАЛОГ` собирает значения состояния служб, подключения камер, очереди регистрации и свободного места. В комплект входят `metrics.prom`, события `events.jsonl` и `traces.json` в формате OTLP JSON. Идентификаторы trace и span связывают событие в системном журнале с вызовом проверки. Состав полей ограничен идентификаторами, состояниями и измерениями. Prometheus может опрашивать `http://127.0.0.1:9464/metrics` на узле. Штатный таймер обновляет метрики каждые десять секунд. [Формат метрик Prometheus](https://prometheus.io/docs/instrumenting/exposition_formats/) · [Формат трасс OTLP](https://opentelemetry.io/docs/specs/otlp/)


Для настройки доверия из локальной консоли запустите `bacuri-vms admin configure-oidc ISSUER CLIENT_ID ADMIN_ACR` и передайте секрет клиента через стандартный ввод. Команда `bacuri-vms admin bind-identity USER_ID ISSUER SUBJECT` привязывает внешний идентификатор к UUID пользователя площадки. Обе операции записываются в аудит. Смена настроек завершает корпоративные сессии площадки, смена привязки завершает корпоративные сессии затронутого пользователя. Восстановление сбрасывает открытые сессии и незавершённые попытки входа. [Управление доступом](ui.md#управление-доступом)
