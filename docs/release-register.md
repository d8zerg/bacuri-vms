# Реестр требований полного выпуска

Реестр связывает возможности автономной VMS с интерфейсами и проверками. Состав исходного среза закреплён в [репозитории](https://github.com/d8zerg/bacuri-vms/tree/13878d9a545333ac870ba05616e240c91097a90d). Для воспроизведения веб-сборки используйте соответствующий lock-файл. [Сервер](../CMakeLists.txt) · [Миграции](../storage/postgresql/migrations) · [Веб-клиент](../web/client/package.json) · [Зависимости клиента](../web/client/package-lock.json) · [REST](../contracts/v1/openapi.yaml) · [WSS](../contracts/v1/alerts.schema.yaml) · [gRPC](../contracts/v1/control.proto) · [Архив](../storage/archive/block-manifest-v1.schema.json)

Для каждой строки одна и та же метка связывает требование, исходные операции и проверку. Область физической и нагрузочной квалификации задаёт профиль. Изменение обязательного сценария, порога или пары оборудования получает новую редакцию с повтором затронутой квалификации на идентифицированном комплекте. [Концепт](concept.md#3-функциональные-требования) · [Профиль полного выпуска](release-profile.md)

## Административные операции полного выпуска

Целевые маршруты ниже относительны к `/api/v1/sites/{siteId}`. Они задают контракт для реализации. Действующие маршруты перечислены в OpenAPI исходной версии. Для изменения политики обязательны административное право в области площадки, проверка версии и запись в аудит. Ответ клиенту содержит идентификатор ресурса, применённую версию и разрешённые следующие действия.

| Задача | Целевой публичный API и результат | Локальная операция |
| --- | --- | --- |
| Пользователи, группы, доступ | `GET/POST /users`, `PATCH /users/{userId}`, `GET/POST /resource-groups`, `PUT /resource-groups/{groupId}`. `PUT/DELETE /grants/{grantId}` назначают или отзывают действие субъекта на точку, группу или интервал, включая экспорт оригинала. `POST /audit/search` ограничивает выдачу областью исполнителя | create-user, grant-point, revoke-point, grant-export, revoke-export используют те же операции C++ |
| Провайдер и внешняя личность | `GET/PUT /identity/provider` задают issuer, client ID и доверенный уровень MFA. Секрет принимается только на запись. `PUT/DELETE /users/{userId}/external-identity` связывают и отвязывают пару iss/sub. Повтор привязки к другому пользователю возвращает конфликт | Установка доверия, первичная привязка и аварийный отзыв ключа администратора доступны из локальной консоли |
| Политика записи и ёмкость | `GET/PUT/DELETE /recording-policies/{policyId}` управляют областью, режимами и сроком. Список политик возвращает итог для каждой настроенной камеры. `GET/PUT /storage/volumes` обслуживают срок и резерв тома, чтение возвращает границы архива и состояние. ## Клиентский контракт

Совместимый клиент сохраняет `site_id`, идентификатор точки и UTC-интервал. Для кадра или команды он также фиксирует версию привязки, фактическое устройство и канал. Замена камеры сохраняет точку. Для расследования сохраняются идентификаторы события, версии правила, дела, удержания и копии. Имена, координаты и URL представлений могут меняться. Новый ресурс получает область площадки и устойчивый идентификатор. Ссылку на медиа клиент получает после проверки текущих прав.

Сервер сообщает доступные операции ресурса для текущего субъекта, модели, прошивки и профиля выдачи. Клиент показывает причину ограничений и повторно запрашивает состояние после изменения прав, устройства или топологии. Мутации с повтором получают ключ идемпотентности, изменения версионированных ресурсов - версию предусловия. Пакетная операция возвращает отдельные результаты устройств. Асинхронная команда имеет ID, срок, владельца и состояния «отправлена», «подтверждена», «результат наблюдён», «отклонена» или «исход неизвестен».

В пределах совместимого API сохраняются действующие поля, значения и семантика. Новое необязательное поле допускает прежний запрос и клиент. Несовместимое изменение получает параллельную основную версию и контрактные примеры для обеих сторон. При неизвестной возможности клиент оставляет остальные операции доступными. Ошибка возвращает HTTP-статус, устойчивый код и идентификатор запроса. Клиент различает отсутствие сессии (401), отказ в праве (403 с учётом правил сокрытия ресурса), конфликт повтора (409), конфликт версии (412), отсутствие предусловия (428) и недоступность зависимости (503). На WSS клиент применяет событие по ID, продолжает после последнего применённого курсора, при `resync_required` получает свежий снимок. Удаление ресурса из области прав закрывает его представления и активную выдачу. [ADR-001](adr/001-api-contracts.md) · [Примеры REST](../tests/contracts/rest.yaml) · [Примеры WSS](../tests/contracts/alerts.yaml)

### Вход через площадку

Площадка публикует доступные способы входа. В автономной установке действуют локальные учётные записи, для администратора обязательны пароль и WebAuthn с проверкой пользователя. При включённом OIDC площадка выступает клиентом Keycloak, начинает Authorization Code Flow с PKCE S256, одноразовыми `state` и `nonce`, проверяет результат по точному доверенному issuer, подписи, audience и сроку. Секрет клиента и токены провайдера доступны только серверу. Администратор площадки явно закрепляет уникальную пару `(iss, sub)` за пользователем Bacuri. Изменение или удаление привязки отзывает связанные сессии и попадает в аудит. Совпадение почты, логина или имени группы не присваивает права. [OpenID Connect Core](https://openid.net/specs/openid-connect-core-1_0.html)

Для административной сессии сервер требует проверенный уровень `acr`, которому доверенная конфигурация realm сопоставляет обязательный второй фактор. При недостаточном уровне нужен повтор с MFA или локальный вход с WebAuthn. Площадка выдаёт собственную сессию, применяет свои права и пишет способ входа и локального исполнителя в аудит. Веб получает штатную защищённую cookie и CSRF-токен. Настольный клиент открывает системный браузер на площадке, получает через зарегистрированный loopback redirect одноразовый код Bacuri со сроком 60 с. Обмен привязан к URI возврата, экземпляру клиента через PKCE S256 и исходному состоянию. Только обмен открывает отдельную сессию приложения. [OAuth для нативных приложений](https://www.rfc-editor.org/rfc/rfc8252)

Выход сначала закрывает сессию Bacuri, её медиасеансы и подписки, клиент очищает локальное состояние всех окон этой сессии. Площадка может завершить также сеанс IdP. Сбой этого запроса сохраняет локальный результат выхода. Отзыв права в Bacuri действует для новых операций сразу, предел остановки активной выдачи 5 с. От блокировки пользователя в Keycloak до отказа его действующих корпоративных сессий Bacuri и остановки их выдачи - максимум 60 с. Бюджет рассчитан на 55 с свежести подтверждённого состояния субъекта и 5 с прекращения передачи. Подтверждение должно учитывать фактическую блокировку в realm. Проверка подписи уже выданного JWT сама по себе не обновляет свежесть. При недоступном провайдере новый корпоративный вход закрыт, действующий доступ исчерпывает тот же бюджет от последнего положительного подтверждения. Локальный администратор сохраняет вход и восстановление. В протоколе зафиксировать версию Keycloak, настройки MFA, способ подтверждения статуса и замеры от блокировки до последнего разрешённого действия.
