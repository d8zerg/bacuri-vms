# Обновление и восстановление Bacuri VMS

[English version](../maintenance.md)

Инструкция описывает обновление, откат и восстановление на Debian Trixie для amd64. Средство обслуживания сверяет установленный пакет со схемой базы и отклоняет неподдерживаемый комплект. Испытательные пакеты имеют суффикс `~qualification`. Сохраните оба подписанных комплекта и независимо доверенные ключи. Команды выполняются в локальной консоли root. Стенд проверяет возврат на независимо подготовленный Debian с установленными пакетами и доступными средствами восстановления. Для работы `bacuri-maintain` на чистом узле сначала установите зависимости штатным установщиком комплекта.

При обновлении службы останавливаются на время миграции. Продолжительность зависит от объёма таблиц карты и архива, для которых перестраиваются индексы. Используйте средство обслуживания из нового подписанного комплекта, сохраните прежний комплект и снимок для отката. После миграции проверьте привязки камер и планов, регионы, калибровку PTZ и действующие права просмотра, управления и экспорта. Версию продукта показывает команда `bacuri-vms --version`. Ожидаемый номер схемы PostgreSQL хранится в поле `Bacuri-Schema` Debian-пакета. Применённый номер показывает запрос `SELECT max(version) FROM bacuri_meta.schema_migrations`.

## Копия и обновление

Предоставьте новый путь для снимка на независимом носителе с доступом только у root. Создайте отдельный 32-байтовый ключ восстановления с правами 0600 и храните резервную копию этого ключа отдельно. Один снимок включает логический дамп PostgreSQL с правами, историей и каталогом, параметры служб, идентификаторы, ключи площадки и сертификаты. Файл зашифрован и аутентифицирован. Видеоблоки и журнал тома храните на отдельном архивном носителе. Индекс локальных назначений рекордера восстанавливается из PostgreSQL. Во время обслуживания `/var/tmp` содержит закрытые для других пользователей временные файлы с открытыми данными. Используйте защищённый системный диск.

```sh
set -eu
umask 077
# Для нового хранилища ключей выберите новый файл.
( set -C; openssl rand 32 > "$key" )
gpgv --keyring "$new_trust" "$new_kit/bacuri-maintain.sig" "$new_kit/bacuri-maintain"
"$new_kit/bacuri-maintain" backup "$online_snapshot" "$key"
"$new_kit/bacuri-maintain" upgrade "$new_trust" "$new_kit" "$upgrade_snapshot" "$key"
```

Периодические копии можно получать на работающем узле. Для целевой RPO прав и конфигурации интервал между успешными снимками должен укладываться в пять минут. Обновление проверяет подпись комплекта и место для снимка, останавливает службы, сохраняет отдельную копию до миграции и запускает службы после её завершения. При прерывании повторите команду с теми же путями. Маркер `/var/lib/bacuri-maintenance/pending` сохраняет запрет запуска служб после перезагрузки.

## Откат и восстановление

Для отката используйте средство обслуживания из нового комплекта, доверенный ключ и пакет версии, указанной в снимке.

```sh
"$new_kit/bacuri-maintain" rollback "$old_trust" "$old_kit" "$upgrade_snapshot" "$key"
```

Команда возвращает конфигурацию, права и историю к моменту копирования. Проверьте изменения прав, выполненные после снимка. Сохранившиеся завершённые блоки того же узла проходят сверку с каталогом.

Для восстановления на чистом узле установите пакет версии снимка без первичной настройки, подключите сохранённый ext4-том в `/srv/bacuri-archive` и верните его запись в fstab. Убедитесь, что в целевой PostgreSQL нет действующей площадки. Передайте комплект той же версии, что и копия.

```sh
"$new_kit/bacuri-maintain" restore "$trust" "$kit" "$snapshot" "$key"
```

При восстановлении прежние браузерные сессии закрываются и привязки WebAuthn сбрасываются. Администратор входит с исходным паролем и заново регистрирует ключ по одноразовому коду локальной консоли. Для утраченного ключа действующей площадки выполните `bacuri-vms admin recover-admin ИМЯ`. Команда отзывает привязку и активные сессии этой учётной записи и выдаёт код на десять минут. После восстановления используйте `bacuri-vms admin enroll-admin ИМЯ`. Журнал действий доступен в `bacuri_access.credential_audit`. На установках со старой схемой проверьте `bacuri_inventory.credential_audit`.

## Диагностика

`bacuri-maintain diagnose НОВЫЙ_КАТАЛОГ` собирает значения состояния служб, подключения камер, очереди регистрации и свободного места. В комплект входят `metrics.prom`, события `events.jsonl` и `traces.json` в формате OTLP JSON. Идентификаторы trace и span связывают событие в системном журнале с вызовом проверки. Состав полей ограничен идентификаторами, состояниями и измерениями. Prometheus может опрашивать `http://127.0.0.1:9464/metrics` на узле. Штатный таймер обновляет метрики каждые десять секунд.

Службы ядра, записи и выдачи медиа каждые десять секунд записывают собственные метрики в свой каталог `/run/bacuri-vms/<служба>/`, а таймер добавляет свежие файлы к пробам. Файл старше минуты не публикуется. Метрики служб измеряют пороги [принципов продукта](product-principles.md#2-скорость-оператора):

| Метрика | Служба | Значение |
| --- | --- | --- |
| `bacuri_http_request_duration_seconds{workload}` | ядро | Время обработки запроса HTTPS для рабочего места (`interactive`), проверки пароля (`credential`) и долгих операций (`long_running`) |
| `bacuri_http_responses_total{workload,status}` | ядро | Ответы по виду нагрузки и классу статуса |
| `bacuri_live_first_frame_seconds` | выдача медиа | Время от запроса эфира до отправки первого кадра зрителю |
| `bacuri_archive_publication_lag_seconds` | запись | Время от приёма последнего кадра блока до его устойчивой записи |
| `bacuri_archive_gaps_total{reason}` | запись | Пропуски записи по причинам |
| `bacuri_archive_verified_bytes_total`, `bacuri_archive_verified_blocks_total{outcome}` | запись | Объём фоновой проверки целостности и её результаты |

[Формат метрик Prometheus](https://prometheus.io/docs/instrumenting/exposition_formats/) · [Формат трасс OTLP](https://opentelemetry.io/docs/specs/otlp/)

Для настройки доверия из локальной консоли запустите `bacuri-vms admin configure-oidc ISSUER CLIENT_ID ADMIN_ACR` и передайте секрет клиента через стандартный ввод. Команда `bacuri-vms admin bind-identity USER_ID ISSUER SUBJECT` привязывает внешний идентификатор к UUID пользователя площадки. Обе операции записываются в аудит. Смена настроек завершает корпоративные сессии площадки, смена привязки завершает корпоративные сессии затронутого пользователя. Восстановление сбрасывает открытые сессии и незавершённые попытки входа. [Управление доступом](ui.md#управление-доступом)

## Вторая копия архива

Подготовьте отдельный носитель и каталог на нём. Для Compose укажите абсолютный путь в `BACURI_REPLICA_MOUNT` и добавьте `-f compose.yaml -f compose.replica.yaml` к командам запуска служб. Рекордер и служба восстановления получают доступ к каталогу на запись, медиасервис - на чтение. Проверьте права владельца и группы по настройкам служб. В нативной установке смонтируйте носитель до запуска служб и задайте `BACURI_ARCHIVE_REPLICA_DIR` с одним путём для рекордера, медиасервиса и команды восстановления. Основной том и том копий должны находиться в разных каталогах. Отказоустойчивость к потере диска требует независимых физических носителей.

Рекордер выделяет отдельный каталог каждой паре площадки и узла. После завершения блока он сверяет манифест, SHA-256 видео и звука и атомарно публикует копию. Страница «Запись и хранение» и команда `bacuri-vms-recorder archive-status` показывают очередь, ошибки проверки, резерв основного тома и прогноз глубины по текущей скорости записи. Проверяйте очередь при изменении числа камер и битрейта.

При повреждении одной копии чтение обращается к сохранной, а фоновая сверка восстанавливает повреждённую. Если утрачены обе, интервал становится недоступным. Восстановление каталога сверяет файлы с манифестами и возвращает действующие удержания до очистки по сроку. Если том копий временно отключён, верните тот же том для выполнения накопленных удалений.
