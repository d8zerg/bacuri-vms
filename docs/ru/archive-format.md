# Формат архива и экспорта

[English version](../archive-format.md)

Архив и подписанные экспорты принадлежат площадке, а не Bacuri. Их форматы - публичный контракт: записанное видео воспроизводится стандартными проигрывателями, а получатель проверяет экспорт стандартными инструментами без доверия к программам Bacuri. JSON Schema находятся в [storage/archive](../../storage/archive).

## Том архива

| Путь | Содержимое |
| --- | --- |
| `journal.db` | Журнал SQLite узла записи. Индексирует блоки и восстанавливается по каталогам блоков при утрате |
| `blocks/<block_id>/manifest.json` | Манифест блока. [Схема](../../storage/archive/block-manifest-v1.schema.json) |
| `blocks/<block_id>/media.mp4` | Фрагментированный MP4 с потоком камеры без перекодирования, H.264 или H.265, начиная с опорного кадра |
| `blocks/<block_id>/audio.pcm` | Звук камеры, если записывается: моно PCM 16 бит little-endian, 8000 Гц, без заголовка |

Медиафайл содержит одну видеодорожку с частотой 90 кГц: `ftyp`, `moov` с конфигурацией декодера (`avcC` или `hvcC`), фрагменты `moof` и `mdat` длительностью около 500 мс и индекс опорных кадров `mfra`. Единицы доступа хранятся без перекодирования. Наборы параметров переносятся в конфигурацию декодера, разделители единиц доступа удаляются. Если камера переупорядочивает кадры, список правок исключает задержку декодирования из показа.

Блок охватывает одну группу кадров, от опорного кадра до следующего. Манифест называет площадку, точку наблюдения, привязку камеры и узел записи, интервал `[begin_utc_us, end_utc_us)` в микросекундах UTC, основание времени с погрешностью, размер и SHA-256 каждого файла. Звук начинается в `audio.start_us`, каждый отсчёт длится 125 микросекунд.

Без Bacuri:

```sh
sha256sum blocks/<block_id>/media.mp4      # совпадает с media.sha256 в манифесте
ffplay blocks/<block_id>/media.mp4
ffplay -f s16le -ar 8000 -ch_layout mono blocks/<block_id>/audio.pcm
```

Для воспроизведения длинного интервала перечислите блоки точки по возрастанию `begin_utc_us` в списке ffmpeg concat.

## Подписанный экспорт

| Файл | Содержимое |
| --- | --- |
| `manifest.json` | Манифест экспорта. [Схема](../../storage/archive/export-manifest.schema.json) |
| `manifest.sig` | Подпись Ed25519 точных байтов `manifest.json`, 128 строчных шестнадцатеричных символов |
| `clip-N.mp4` | Видео N-го записанного периода |
| `audio-N.wav` | Звук N-го записанного периода, моно PCM 16 бит, 8000 Гц, если звук экспортирован |

Периоды манифеста покрывают интервал экспорта без наложений. Период `gap` называет причину отсутствия видео, например `source_offline` или `no_frame`. Период `recorded` называет свой фрагмент, манифест исходного блока архива и преобразование:

| Преобразование | Значение |
| --- | --- |
| `original` | Неизменённый блок архива. Его SHA-256 равен `source.media.sha256` |
| `original_with_decode_context` | Неизменённый блок, который содержит и кадры вне периода, потому что они нужны для декодирования |
| `h264_frame_selection` | Только кадры периода, перекодированные |
| `h264_masked_selection` | Только кадры периода, перекодированные с масками приватности площадки |

Формат `bacuri.vms.export.v2` добавляет режим экспорта, основание, кодек, маски и звук каждого периода.

## Дело расследования

Пакет дела содержит подписанный корневой манифест и по одному подписанному экспорту на материал в каталогах `material-1`, `material-2` и далее. Корневой манифест фиксирует SHA-256 манифеста каждого материала. [Схема](../../storage/archive/case-manifest-v1.schema.json)

## Доверенный ключ

Получатель получает открытый ключ площадки по доверенному каналу, например лично от администратора площадки. [Схема](../../storage/archive/trusted-key.schema.json)

```json
{"site_id": "10000000-0000-4000-8000-000000000001", "algorithm": "Ed25519", "public_key": "<64 шестнадцатеричных символа>"}
```

## Алгоритм проверки

1. Проверить подпись Ed25519 из `manifest.sig` над точными байтами `manifest.json` доверенным ключом. Принимается только манифест площадки, указанной в ключе.
2. Для дела: проверить, что каталог каждого материала существует, SHA-256 его `manifest.json` равен `manifest_sha256`, и проверить материал как экспорт. Его точка, интервал и режим совпадают с частью дела.
3. Для экспорта: проверить, что периоды начинаются в `begin_utc_us`, следуют друг за другом без разрывов и заканчиваются в `end_utc_us`.
4. Для каждого записанного периода: SHA-256 и размер фрагмента совпадают с манифестом, период лежит внутри исходного блока, фрагмент `original` побайтно равен исходному блоку.
5. Для каждого экспортированного звука: заголовок WAV занимает 44 байта, размер равен 44 плюс два байта на каждые 125 микросекунд периода, SHA-256 совпадает с манифестом.
6. В каталоге нет файлов, кроме названных в манифесте.

Пакет, не прошедший любой шаг, отклоняется целиком.

## Средства проверки

Поддерживаемое средство - `bacuri-vms-verify-export TRUSTED_PUBLIC_KEY.json EXTRACTED_DIRECTORY`. Оно выводит проверенный манифест и возвращает ненулевой код для отклонённого пакета. Утилита зависит только от libsodium и JSON и собирается без тома архива, SQLite и GStreamer: `cmake --build build/gcc-release --target bacuri-vms-verify-export`.

[reference_verifier.py](../../tests/archive/reference_verifier.py) реализует тот же алгоритм на стандартной библиотеке Python и утилите openssl и не использует код Bacuri. Сценарии экспорта требуют, чтобы оба средства принимали каждый подлинный пакет и отклоняли каждый изменённый.

Отдельно подпись проверяется OpenSSL 3:

```sh
key=$(python3 -c 'import json,sys; print(json.load(open(sys.argv[1]))["public_key"])' trusted-key.json)
printf '302a300506032b6570032100%s' "$key" | xxd -r -p | openssl pkey -pubin -inform DER -out key.pem
xxd -r -p manifest.sig > manifest.sig.bin
openssl pkeyutl -verify -pubin -inkey key.pem -rawin -in manifest.json -sigfile manifest.sig.bin
sha256sum clip-*.mp4 audio-*.wav    # сравнить с sha256 периодов в manifest.json
```
