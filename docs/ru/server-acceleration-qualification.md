# Квалификация серверного ускорения

[English version](../server-acceleration-qualification.md)

Для каждого прогона создаётся отдельный проект Compose с PostgreSQL и синтетической камерой во внутренней сети. В контейнер исполнителя копируются файлы release-сборки, сохраняются их контрольные суммы и выполняется проверка узла. Серии измерений на одном узле запускаются последовательно. Каждая проверка, включая пробу узла, ограничена десятью минутами. Сборка образов и подготовка стенда выполняются до запуска проверки. Четыре входных профиля - H.264 Main и H.265 Main в 1920x1080 и 2560x1440, 25 кадров/с, по 150 кадров SMPTE в 8-битном формате 4:2:0, с целевым битрейтом 6 Мбит/с, секундным GOP и без B-кадров. Входные файлы и тестовые учётные данные существуют только внутри контейнера проверки. Отчёты в `build/acceleration/qualification/<backend>-<phase>-<run>/` сохраняются после удаления контейнера.

| Проверка | Команда | Результат |
| --- | --- | --- |
| Производительность | `task acceleration:qualify BACKEND=cpu PHASE=capacity` | Устройства, результат проверки узла, бюджеты, данные отдельных исполнителей, медианная скорость экспорта и анализа архива |
| Отказы | `task acceleration:qualify BACKEND=nvidia PHASE=faults` | Последовательность кадров эфира с маской, фактические переходы между устройствами и непрерывность записи штатным сервисом |
| Переменная нагрузка | `task acceleration:qualify BACKEND=nvidia PHASE=soak` | Непрерывная работа в режиме «Авто», замеры памяти по фазам нагрузки, счётчики кадров и переключений |

Для измерения производительности на GPU укажите `BACKEND=nvidia` или `BACKEND=vaapi`. Для VA-API задайте `BACURI_RENDER_DEVICE` и `BACURI_RENDER_GID` согласно устройству рендеринга и его группе на хосте. На узле без проверенного GPU доступен режим «Только CPU». Серию NVIDIA повторяют для каждой модели и драйвера. Вместе с замерами сохраняют отпечаток проверки узла.

## Измерения и приёмка

- Каждый исполнитель декодирует вход через штатный конвейер эфира, наносит маску или формирует отдельный профиль H.264 и сверяет время каждого выходного кадра. Учитываются серии, где каждый исполнитель выдал все 150 кадров. После первых двух секунд входного видео каждый кадр должен поступить с задержкой до секунды относительно входных часов. Старт входных часов исполнителей в серии должен укладываться в одну секунду. Для каждого потока отдельно сохраняются время до первого кадра и максимальная задержка с учётом запуска. `BACURI_DENSITY_LIMIT` задаёт максимальное число одновременных потоков, по умолчанию восемь. Успешная проверка на этом пределе даёт нижнюю оценку плотности. Отчёты исполнителей показывают, какие потоки обрабатывались на GPU и какие перешли на CPU.
- Экспорт выбирает и маскирует все 150 кадров. Анализ архива строит опорный кадр, миниатюру и индекс движения. Проверяется количество кадров. Скорость в кадрах/с - медиана трёх запусков отдельных процессов с учётом запуска, завершения и вывода результата. Вход подаётся без ограничения по часам. В ручном режиме выбирается один измеряемый вид задач. Подзадачи анализа архива могут работать на разных устройствах. Результат проверки узла и предварительный расчёт размещения содержат бюджеты сессий, времени и памяти.
- Во время отказов штатный сервис записи сохраняет исходный поток тестовой RTSP-камеры, а отдельный исполнитель обрабатывает эфир 1080p в реальном времени. В каждом полном блоке проверяют 25 кадров, отсутствие разрывов исходных меток времени больше половины кадра и отсутствие пропусков в каталоге. Отдельно проверяются сообщение о сбросе драйвера, скрытие устройства от нового исполнителя, отказ CUDA в выделении объёма больше физической памяти с последующим сообщением исполнителя об ошибке и фактическое исчерпание сессий кодера. Для физического сброса драйвера, отключения устройства и заполнения свободной VRAM требуется выделенный GPU.
- В режиме «Авто» один исполнитель эфира H.264 1080p с маской по умолчанию работает 120 секунд (3000 кадров). Нагрузка чередуется каждые 15 секунд. В фазе высокой нагрузки добавляется профиль HEVC 2K с экспортом или анализом архива. RSS суммируется для Core, Media и постоянного исполнителя. Видеопамять суммируется по тем же процессам, отдельно сохраняется значение постоянного исполнителя. На NVIDIA используются показания драйвера по процессам, на VA-API - счётчики резидентной локальной памяти, если их предоставляет DRM. Рост определяется по медианам первых и последних трёх сопоставимых замеров в фазе малой нагрузки после прогрева. Потеря телеметрии, пропуск кадров, превышение задержки или лимита исключают успешный результат.
- Для локальной проверки предел прироста RSS и VRAM составляет по 128 МиБ. Постоянный эфир с маской должен остаться на исходном устройстве. Каждый добавленный профиль может один раз перейти с CPU на GPU, когда фоновая задача освободит устройство. Общий лимит по умолчанию - одно переключение на фазу высокой нагрузки (четыре в контрольном прогоне). Перед запуском значения из паспорта конкретного узла можно задать через `BACURI_RSS_GROWTH_MIB`, `BACURI_VRAM_GROWTH_MIB` и `BACURI_SWITCH_LIMIT`. Через `BACURI_SOAK_SECONDS` можно запросить 48-600 секунд видео. Если после пробы узла остаётся меньше времени, интервал сокращается с учётом десятиминутного предела. Запрошенный и фактический интервалы сохраняются в отчёте. Время работы и состояние отражаются в `status.json`. После остановки или перезапуска отсчёт начинается заново.

## Контрольный узел

AMD Ryzen 9 3900X (12 ядер, 24 потока), Linux 7.0.0-44-generic. Профиль без GPU работает в контейнере без доступа к видеоустройствам. Профиль GPU использует тот же узел с GeForce RTX 4070 Ti и драйвером 595.99.02. Проверка подтвердила отдельно 12 сессий кодирования H.264 и 12 сессий HEVC. Кодеки делят общий предел аппаратного кодера. На этом стенде пока нет измерений для серверной NVIDIA и работающего устройства VA-API.

| Вход, только CPU | Одновременный эфир с масками | Одновременные профили | Экспорт с маской, кадров/с | Анализ архива, кадров/с |
| --- | ---: | ---: | ---: | ---: |
| H.264 1080p | ≥8 | ≥8 | 230,02 | 130,27 |
| H.265 1080p | ≥8 | ≥8 | 212,63 | 112,43 |
| H.264 2K | ≥8 | ≥8 | 160,94 | 79,64 |
| H.265 2K | ≥8 | ≥8 | 140,48 | 73,45 |

Каждый столбец плотности измерен в отдельной серии. Проверка узла CPU указала один подтверждённый эталонный поток 25 кадров/с для каждого кодека и направления. В режиме «Только CPU» сессии аппаратного кодера и видеопамять не резервируются.

В серии измерения плотности GPU проверка узла указала 11,56 ГиБ видеопамяти и бюджет 1 000 000 единиц времени в секунду. Эталонный эфир с маской или отдельный профиль занимает 40,78% этого бюджета и одну сессию кодера H.264. Предварительный расчёт «Авто» для эталонного набора задач резервирует две сессии, 91,91% бюджета времени и 4,30 ГиБ. Рабочее размещение зависит от фактически запущенных задач.

За 220 секунд проверки отказов получены все 5500 кадров эфира с маской. После запуска максимальная задержка кадра составила 360 мс. За контрольный интервал с граничными блоками сервис записи опубликовал 222 последовательных GOP (5550 кадров). В каталоге нет пропусков. Сообщение о сбросе, скрытие CUDA у исполнителя и отказ в заведомо слишком большом выделении памяти с сообщением об ошибке дали по одному переходу GPU -> CPU -> GPU. Когда все 12 сессий NVENC были заняты, новый исполнитель обработал 150 кадров на CPU, а уже работающий эфир сохранил свой кодер. В журнале узла зарегистрирован `session_limit`.

## Режимы на RTX 4070 Ti

В столбцах плотности указано число потоков на GPU и на CPU при восьми запущенных исполнителях. Экспорт и анализ измерялись отдельно от плотности, при одном задании. В ручном режиме аппаратное ускорение включалось для измеряемого вида задач.

| Вход | Режим | Маски, GPU + CPU | Профили, GPU + CPU | Экспорт, кадров/с | Анализ архива, кадров/с |
| --- | --- | ---: | ---: | ---: | ---: |
| H.264 1080p | Только CPU | 0 + 8 | 0 + 8 | 209,62 | 129,84 |
| H.264 1080p | Авто | 2 + 6 | 2 + 6 | 117,69 | 73,14 |
| H.264 1080p | Вручную | 2 + 6 | 2 + 6 | 117,31 | 82,06 |
| H.265 1080p | Только CPU | 0 + 8 | 0 + 8 | 187,36 | 108,48 |
| H.265 1080p | Авто | 2 + 6 | 2 + 6 | 112,29 | 70,71 |
| H.265 1080p | Вручную | 2 + 6 | 2 + 6 | 114,35 | 78,75 |
| H.264 2K | Только CPU | 0 + 8 | 0 + 8 | 149,79 | 80,21 |
| H.264 2K | Авто | 2 + 6 | 2 + 6 | 99,31 | 54,48 |
| H.264 2K | Вручную | 2 + 6 | 2 + 6 | 98,15 | 60,28 |

Во всех успешных сериях на восьми исполнителях первый кадр поступил через 120-160 мс на CPU и через 1080-1280 мс на NVIDIA. После двух секунд входного видео максимальные измеренные задержки кадра составили 84 мс на CPU и 81 мс на NVIDIA. Для шестисекундных заданий экспорта и анализа архива режим «Только CPU» был быстрее на всех четырёх входах. Время каждого задания включает запуск процесса и создание контекста кодека.

В двухминутной проверке с переменной нагрузкой получены 3000 кадров с маской и пройдены четыре фазы высокой нагрузки. Постоянный поток остался на RTX. Два дополнительных профиля начали на CPU и затем получили GPU. Прирост RSS в сопоставимых замерах составил 0,13 МиБ, VRAM - 0 МиБ.
