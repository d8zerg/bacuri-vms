# Принципы продукта Bacuri VMS

[English version](../product-principles.md)

Документ задаёт свойства, в которых Bacuri VMS должна быть лучше всех доступных VMS, и свойства, где достаточно уровня лидеров. Проектные решения, ADR и ревью кода сверяются с этим документом. [Профиль приёмки](release-profile.md)

## Позиционирование

Bacuri VMS - свободная платформа видеонаблюдения под лицензией MIT. В ней нет лицензий за камеру, привязки к производителю оборудования, зависимости от облака и обязательного интегратора. Любая площадка получает возможности, которые обычно доступны только в коммерческих VMS: проверяемый архив, разграничение прав, аудит и расследование.

Успех продукта определяется тем, что люди без участия автора могут установить систему, понять её, проверить её данные, доработать и продолжить развитие.

## Приоритетные свойства

Статус: **Принято.** Порядок задаёт приоритет при конфликте свойств.

1. Открытость.
2. Скорость оператора.
3. Достоверность архива.

ИИ-исполнитель становится приоритетным свойством после достижения порогов первых трёх.

Пороги ниже - целевой уровень продукта. Пороги [профиля приёмки](release-profile.md#измерения-и-пороги) остаются минимальным условием выпуска.

### 1. Открытость

Открытость означает не только лицензию, но и независимость пользователя от проекта и его автора.

| Требование | Проверка |
| --- | --- |
| Данные принадлежат площадке | Запись и экспорт воспроизводятся стандартными проигрывателями и ffmpeg без компонентов Bacuri. Формат каталога и манифеста архива описан и версионируется. [Формат архива и экспорта](archive-format.md) |
| Проверка без доверия к Bacuri | Алгоритм проверки экспорта опубликован, утилита проверки собирается из исходников отдельно от сервера |
| Открытые контракты | Любую операцию веб-клиента можно выполнить через опубликованный API. Закрытых внутренних путей для клиента нет |
| Оборудование любого производителя | Базовые сценарии работают через ONVIF и RTSP. Адаптеры производителей только расширяют функции |
| Низкий порог участия | От клонирования репозитория до стенда с синтетической камерой и записью - одна команда и не более 15 минут на типовой машине разработчика |
| Документация для всех | Основной язык README и документации - английский, второй - русский. Английская версия - источник, русская обновляется в том же изменении |
| Проверяемая поставка | Повторная сборка комплекта из того же коммита в той же среде даёт совпадающие хеши артефактов. SBOM входит в комплект |
| Доступное железо | Компактный профиль выполняет пороги приёмки на недорогом x86-64 мини-ПК без дискретной видеокарты |

### 2. Скорость оператора

Действующие пороги приёмки (p95 до 2 с) соответствуют уровню лидеров. Для приоритетного свойства нужен отдельный, более строгий уровень.

| Показатель | Целевой порог в локальной сети |
| --- | --- |
| Видимая реакция интерфейса на действие | p95 до 100 мс |
| От выбора камеры до первого декодированного кадра эфира | p95 до 500 мс |
| От приёма события до видимой карточки тревоги | p95 до 500 мс |
| От карточки тревоги до кадра архива в момент события | одно действие, первый кадр p95 до 1 с |
| Основные операции оператора | доступны с клавиатуры без мыши |
| Переходы эфир -> архив -> план -> тревога | камера, время и место сохраняются без повторного выбора |

### 3. Достоверность архива

Система никогда не сообщает больше, чем подтверждено фактическими данными.

| Требование | Проверка |
| --- | --- |
| Статус записи выводится из архива | Признак «идёт запись» показывается, только если в каталоге зафиксирован кадр не старше заданного интервала. Настройка записи сама по себе статусом не является |
| Пропуски видны всегда | Каждый пропуск на шкале имеет причину: нет потока, остановка записи, отказ носителя, удаление по сроку |
| Время с неопределённостью | Участки с неизвестной или скорректированной привязкой времени отмечены в интерфейсе и экспорте |
| Целостность от записи до экспорта | Изменение любого блока архива обнаруживается проверкой. Экспорт проверяется автономно |
| Защищённые фрагменты | Защищённый фрагмент не удаляется ни по сроку хранения, ни при заполнении носителя |
| Эфир не путается с записью | При ручной приёмке ни один участник не принимает эфир за запись |

### Позже: ИИ-исполнитель

До перехода к этому свойству архитектура не должна его закрывать. Любое действие выполняется через общий слой авторизованных команд, тип исполнителя фиксируется в аудите.

## Интерфейс

Статус: **Принято.**

Интерфейс задаёт правила для отрасли, а не повторяет устройство существующих VMS. Цель - превзойти лидеров в эргономике, простоте, удобстве и оформлении. Интерфейс воплощает приоритетные свойства: скорость оператора и достоверность архива видны в каждом экране.

### Модели взаимодействия

| Модель | Правило |
| --- | --- |
| Единая шкала времени | Эфир и архив - одна поверхность просмотра. Эфир - правый край шкалы, переход назад во времени выполняется прокруткой шкалы без смены раздела и без перезапуска просмотра |
| Командная строка | Ctrl+K открывает поиск по точкам, планам, тревогам и действиям. Запрос вида «ворота 2 вчера 22:00» открывает точку в указанный момент |
| Тревога как сессия разбора | Открытая тревога показывает на одном экране кадр момента события, эфир, точку на плане и доступные действия. Следующая и предыдущая тревога, принятие, закрытие и эскалация выполняются одной клавишей |
| Единый индикатор записи | У точки один составной индикатор состояния. Он выводится из каталога архива и показывает возраст последнего записанного кадра. Связь, эфир и запись раскрываются в подробностях индикатора |
| Подключение без адресов | Пустая площадка сразу запускает обнаружение камер. Администратор выбирает камеры и вводит учётные данные. Живой список проверок сам проходит шаги поток -> запись -> кадр из архива. Ввод адресов RTSP - запасной путь |
| Видео - главный объект | На пульте оператора видео занимает основную площадь экрана. Навигация и панели сворачиваются и не отнимают площадь у кадра |

### Правила по умолчанию

- Пульт оператора и настройки администратора - разные рабочие пространства с собственной навигацией. Администратор переключается между ними одним действием.
- Пульт оператора по умолчанию использует тёмную тему. Выбор темы пользователем сохраняется.
- Время показывается в часовом поясе площадки с относительным временем для свежих событий. UTC и смещение доступны в подробностях, экспорте и аудите.
- Восстановление после отказа закрывает или обновляет исходную тревогу и не создаёт новую тревогу.
- Важность тревоги различима до чтения текста: по положению в ленте, форме и цвету метки.
- Одно состояние показывается в одном месте. Дублирующие подписи состояния убираются.
- Пустой экран называет следующий шаг и даёт действие для него.
- Навигация отражает задачи пользователя, а не устройство реализации. Глубина меню - не более двух уровней.
- Масштаб плана и карты меняется прокруткой и жестами.

### Оформление

- Собственный визуальный язык профессионального инструмента: плотный, спокойный, с приоритетом содержимого. Шаблонная компоновка панели администрирования не используется для пульта оператора.
- Цвет обозначает состояние и основное действие. Декоративные цвета не используются.
- Вложенные контейнеры с рамками не используются. Группировка задаётся отступами и типографикой.
- Все элементы управления используют общие компоненты и токены. Нестилизованные системные элементы управления на рабочих экранах не используются.

### Пороги

| Показатель | Целевой порог |
| --- | --- |
| Доля площади экрана 1440x900 под видео при просмотре одной точки на пульте | не менее 70% |
| Переход к точке в заданный момент через командную строку | ввод запроса и одно подтверждение |
| От тревоги до кадра момента события | одно действие |

| Разбор очереди тревог | все действия разбора доступны с клавиатуры одной клавишей |

## Уровень лидеров

Федерация, кластер, PTZ, карты, интеграции и остальные функции выполняют пороги профиля приёмки. Превосходство в них не является целью, пока не достигнуты пороги приоритетных свойств.

## Ограничения

- Функция не принимается, если ухудшает приоритетное свойство: замедляет первый кадр, делает статус записи косвенным или требует закрытого формата.
- Основные сценарии не зависят от облака и внешних сервисов.
- Архив не хранится в форматах, которые нельзя прочитать без Bacuri.
- Новая технология принимается, когда даёт измеримый выигрыш по приоритетному свойству или требуется политикой технологий. [ADR-015](adr/015-technology-lifecycle.md)
- Широта поддержки функций камер не важнее надёжности базовых сценариев.

## Применение

- ADR и крупные изменения указывают влияние на каждое приоритетное свойство.
- Ревью кода сначала проверяет приоритетные свойства, затем остальные критерии [качества](quality.md).
- Целевые пороги измеряются в прогоне релиз-кандидата вместе с порогами профиля приёмки. Невыполненный целевой порог фиксируется как отклонение, но не блокирует выпуск.
