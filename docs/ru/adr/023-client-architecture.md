# ADR-023. Архитектура Bacuri VMS Client

[English version](../../adr/023-client-architecture.md)

**Статус** - Принято.

**Контекст.** Bacuri VMS Client - настольное рабочее место Bacuri VMS для операторов и администраторов. Он достигает паритета с веб-клиентом и добавляет многомониторный пост, видеостену, синхронный архив всей раскладки, прямое управление PTZ, физический пульт, пространственную навигацию между камерами и автономную проверку экспорта. Его первые части - измеренные пути видео и карты из [ADR-022](022-desktop-video-path.md) и сеанс настольного клиента из [ADR-001](001-api-contracts.md#локальная-сессия-и-правила-доступа). Клиент работает неделями без перезапуска, показывает 16 и более видеопотоков рядом с картой и должен оставаться отзывчивым под нагрузкой, поэтому его структура с самого начала держит под контролем потоки, состояние и визуальную систему.

**Решение.** Клиент - приложение на C++23 и Qt 6 Quick. C++ владеет состоянием, медиа, сетью и работой. QML отвечает за представление. Код разделён на слои и модули с объявленными зависимостями, как модули ядра площадки.

| Слой | Модули | Ответственность |
| --- | --- | --- |
| Приложение | `app` | Окна по экранам, навигация между рабочими областями, реестр команд, сохранение и восстановление поста, язык и тема |
| Функции | `live`, `archive`, `alerts`, `maps`, `investigations`, `export`, `administration`, `help` | Один модуль на рабочую область реестра паритета. Модели C++ с типизированными свойствами и представления QML. Функция зависит от базовых служб и никогда от другой функции: другую область она открывает через намерение навигации приложения |
| Базовые службы | `site`, `media`, `map`, `input`, `settings`, `diagnostics` | Клиент API, сеанс, лента событий и каталог ошибок площадки. Видеопотоки, выбор декодера, откат, общие подписки и кэш кадров. Представление карты и шлюз ресурсов площадки. Джойстики и клавишные панели. Настройки по пользователю и площадке. Журналы, метрики и время кадра |
| Дизайн-система | `ui` | Токены, компоненты и элементы графа сцены визуальной системы как QML-модуль `Bacuri.Vms.Client.Ui` со своим каталогом и проверкой снимками экрана |

Каждый модуль - библиотека в `desktop/src/<module>` со своими тестами. Инструменты, которые измеряют или проверяют клиент, например измерительный стенд видео и карты и проверка входа, находятся в `desktop/tools` и используют те же библиотеки.

| Правило | Содержание |
| --- | --- |
| Потоки | В потоке GUI работают только QML и модели. Поток отрисовки рисует граф сцены, текстуры видео и карту. Каждый медиаконвейер и его декодер работают в своих потоках, сетевые запросы асинхронны. Ничто не блокирует поток GUI. Потоки обмениваются данными через сигналы в очереди и ограниченные очереди, которые отбрасывают устаревшие кадры и считают их |
| Состояние | У каждого объекта площадки один владелец в базовых службах: кэш по идентификатору с версией или ETag, обновляемый из ответов и ленты событий. Функции хранят только состояние представления. Состояние поста - окна на экранах, раскладки, открытые тревоги, позиции архива и фокус - одна сериализуемая структура, которая сохраняется атомарно и восстанавливается с повторной проверкой прав |
| Команды | Каждое действие пользователя - команда с идентификатором, названием на обоих языках, сочетанием клавиш, значком и правилом доступности по правам и возможностям площадки. Меню, командная строка, радиальное меню, сочетания клавиш и физический пульт вызывают один реестр команд |
| Контракты | Типы C++ и кодеки JSON для API генерируются из контракта OpenAPI. Коды ошибок, классы повтора и сообщения берутся из каталога ошибок, общего с веб-клиентом. Функция, которой нужна более новая площадка, проверяет версию API и возможности площадки и скрывается на прежней |
| Язык | Сообщения на английском и русском хранятся по ключам, как в веб-клиенте. Смена языка меняет все окна без перезапуска и без потери ввода, фокуса и воспроизведения |
| Отказы | У каждого видимого человеку состояния есть причина из каталога ошибок или локальная причина клиента. Клиент не закрывает окно из-за отказа сети, камеры, декодера или графического устройства: он деградирует и восстанавливается, как описано в ADR-022 |

**Архитектура интерфейса.**

| Часть | Решение |
| --- | --- |
| Визуальная система | Токены `design/bacuri/tokens.css` генерируются в QML-синглтон: цвета обеих тем, шкала шрифтов, отступы, радиусы, толщины линий, длительности движения и параметры пружин. Веб- и настольный клиенты поэтому используют одну палитру и один набор цветов состояний |
| Компоненты | Небольшие QML-компоненты с явным API для панелей, полей, кнопок, меток, таблиц и диалогов. У компонента есть состояния загрузки, отсутствия данных, отказа и отсутствия прав, видимый фокус клавиатуры и доступное имя |
| Тяжёлая графика | Сетка видео, шкала времени, наложения в кадре, секторы обзора и пространственная сцена - элементы графа сцены на C++ с шейдерами, а не сотни QML-объектов на кадр |
| Взаимодействие | Принципы рабочего места - требования к каждому компоненту: изображение показывается целиком и в исходном цвете, позиции ячеек меняются только действием оператора, ввод приоритетнее видео, цвет обозначает состояния и дублируется формой или текстом, движение короткое и отключается, каждое частое действие доступно без поиска кнопки |
| Экраны | Экраны следуют [макетам рабочего места оператора](../desktop-ui.md): стена мониторинга, камера в фокусе, синхронный архив, обработка тревоги, командная строка, план, анатомия ячейки и пост из трёх мониторов |
| Доступность | Работа с клавиатуры во всех сценариях, роли и имена для экранного диктора, масштаб текста, DPI каждого монитора и проверка контраста обеих тем |

**Именование.** Продукт - Bacuri VMS Client, исполняемый файл `bacuri-vms-client`, пространство имён C++ `bacuri::vms::client`, QML-модули `Bacuri.Vms.Client.*` и библиотеки `bacuri-vms-client-<module>`.

**Обоснование и последствия.** Разделение функций и базовых служб сохраняет одного владельца каждого объекта и один путь для каждого вида работы, поэтому два окна не показывают разные версии одной тревоги, а медленная камера не блокирует интерфейс. Реестр команд даёт клавиатуре, пульту и меню одно поведение и одно место проверки прав. Генерация типов API и токенов убирает ручные копии контракта и палитры. Структура требует явных границ модулей и генерируемого кода, что окупается по мере роста сценариев паритета и функций рабочего места. [Граница модулей ядра](018-core-module-boundary.md) · [Каталог ошибок](020-error-catalog.md) · [Путь видео и карты](022-desktop-video-path.md)

**Проверка.** Сборка связывает каждый модуль только с объявленными зависимостями, функция, подключающая другую функцию, не проходит проверку архитектуры. Каждый модуль сохраняет покрытие строк не ниже 75% своими тестами. Компоненты проверяются снимками экрана в обеих темах и на обоих языках, сценариями клавиатуры и доступными именами. Измерительный стенд и проверки на стенде измеряют время кадра, путь кадра и восстановление после отказов на стендах паспорта.
