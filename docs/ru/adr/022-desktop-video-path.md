# ADR-022. Путь видео и карты настольного клиента

[English version](../../adr/022-desktop-video-path.md)

**Статус** - Принято для Linux. Путь видео на Windows и macOS проверяется на стенде каждой ОС по [плану поддержки дополнительных платформ](../devplan-desktop-platforms.md).

**Контекст.** Настольный клиент показывает эфир и архив до 16 камер на одном экране рядом с картой. Кадр должен попадать на экран без копирования через системную память, интерфейс должен оставаться отзывчивым под нагрузкой, а пост должен продолжать работу при отказе GPU или его декодера. Qt Quick умеет рисовать через разные графические API, GStreamer даёт аппаратные и программные декодеры, MapLibre Native for Qt даёт модуль Qt Location и библиотеку ядра.

**Варианты.**

| Вариант | Оценка |
| --- | --- |
| Декодирование в системную память и загрузка каждого кадра | Работает везде, но даёт одно копирование на кадр и 4-6 ядер CPU на 16 камер 1080p |
| Аппаратное декодирование в память OpenGL и `qml6glsink` | Ноль копирований через системную память, 2,4 ядра CPU на 16 камер. Требует графический API OpenGL у Qt Quick |
| Собственный узел RHI с импортом поверхностей декодера | Работает с любым графическим API, но требует импорта памяти декодера для каждой платформы до первого полезного экрана |
| Карта через модуль Qt Location из MapLibre | Требует закрытых заголовков Qt Location, которых нет в Debian, исходники модуля под LGPL или GPL |
| Карта через ядро MapLibre и собственный элемент Qt Quick | BSD-2-Clause, без зависимости от Qt Location, карта рисуется в буфер кадра OpenGL той же сцены |

**Решение.** На Linux клиент использует Qt Quick на OpenGL. Каждая ячейка декодирует через NVDEC, когда он доступен, затем через VA-API, и передаёт кадр в памяти OpenGL в `qml6glsink`. Конвейеры процесса используют общие контексты CUDA, VA и дисплея GL, поэтому устройство инициализируется один раз. Ячейки сетки воспроизводят запись на общей шкале времени: одни системные часы и одно базовое время для всех конвейеров, подготовка и перемотка в рабочих потоках не более четырёх ячеек одновременно. Живые источники воспроизводятся по мере прихода кадров. Карту рисует собственный элемент `QQuickFramebufferObject` поверх ядра MapLibre Native for Qt, собранного из закреплённого выпуска без интеграции с Qt Location. Карта приходит с площадки: MapLibre сама загружает стиль и тайлы и не умеет добавлять bearer-токен, поэтому клиент переписывает адреса площадки на локальный шлюз `127.0.0.1` со случайным секретным путём, а шлюз передаёт каждый запрос площадке с токеном и доверенными сертификатами площадки.

| Ситуация | Поведение |
| --- | --- |
| Аппаратный декодер доступен | NVDEC, кадры остаются в памяти GPU |
| Аппаратного декодера нет при запуске | Программный декодер, одна загрузка на кадр |
| Аппаратный декодер отказал во время воспроизведения | Ячейка пересобирает конвейер с программным декодером и продолжает с последнего показанного кадра. Окно, раскладка и остальные ячейки продолжают работу |
| GPU отсутствует | Клиент распознаёт программный рендерер OpenGL до открытия окна, декодирует программно и ограничивает каждую ячейку размером 640x360 и частотой 15 к/с. Отрисовка идёт через Mesa. Пост работает с меньшей плотностью |
| Графическое устройство потеряно во время отрисовки | Клиент перезапускается в режиме программной отрисовки и восстанавливает пост: раскладки, тревоги, позицию архива и фокус |

Поддерживаемая плотность указывается для каждого стенда по измеренным прогонам: на эталонном стенде 16 камер 1080p 25 к/с занимают 2,4 ядра CPU с NVDEC, интерфейс сохраняет частоту экрана 60 Гц с интервалом кадров p99 17-20 мс при обычном воспроизведении, карта добавляет 0,2 мс на кадр. Сетка 16 ячеек запускается за 1,6 с и перематывается за 0,9 с, самый долгий кадр интерфейса не превышает 40 мс, ячейки расходятся не больше чем на 2 кадра. Без GPU 16 ограниченных ячеек занимают 14 ядер CPU при интервале кадров p99 45 мс. В контейнере окно попадает на экран только с устройствами DRI хоста.

**Обоснование и последствия.** Путь через OpenGL уже сейчас даёт ноль копирований на эталонном стенде, а собственный узел RHI отложил бы первый рабочий экран из-за импорта поверхностей для каждой платформы. Решение привязывает клиент к графическому API OpenGL у Qt Quick на Linux. Для Windows и macOS нужно отдельное решение: в GStreamer есть приёмники Direct3D 11 и Metal, элемент карты должен следовать выбранному API. Одновременный сброс многих аппаратных декодеров занимает графический драйвер и задерживает кадр интерфейса до 0,45 с на 16 ячейках H.265, поэтому сетка ограничивает параллельные шаги четырьмя ценой более медленной перемотки. Каждый `qml6glsink` создаёт свой контекст GL, это ограничивает запуск сетки. Приёмник сетки или узел графа сцены с одним контекстом и кэш опорных кадров для синхронного архива остаются в работе. Элемент карты избавляет клиент от кода под LGPL и GPL. [Жизненный цикл технологий](015-technology-lifecycle.md) · [Источники карт](017-map-sources.md)

**Проверка.** `task desktop:video` прогоняет эталонные записи H.264 и H.265, живые камеры, карту рядом с 16 ячейками, отказ декодера во время воспроизведения и стенд без доступа к GPU на 4-16 ячейках. Каждый прогон проверяет первый кадр, кадр после перемотки или после отката, память на выходе декодера, расхождение показанных кадров между ячейками и отсутствие ошибок. `task desktop:passport` привязывает результаты к измеренному стенду.
