# ADR-019. Загрузка данных в веб-клиенте

[English version](../../adr/019-client-data-loading.md)

**Статус** - Принято.

**Контекст.** Экраны единого клиента читают данные площадки через интерфейс `Services`. Этот же интерфейс реализуют серверные адаптеры и фикстура Storybook. Каждый экран загружал данные в своём `useEffect` с `AbortController`, своим признаком сбоя и своим счётчиком обновления. Экран карт дополнительно опрашивал сцену. Правила для устаревшего ответа, временного сбоя и обновления различались между экранами. [ADR-014. Единый веб-клиент](014-web-client.md)

**Варианты.** Загрузчики React Router читают данные на уровне маршрута. Большинство чтений клиента относится к вкладке, диалогу или выбранному объекту внутри одного маршрута, а сцена карт опрашивается, поэтому загрузчики покрывают часть чтений. TanStack Query даёт кеш, отмену, повторы, опрос и инвалидацию и добавляет в автономный комплект зависимость со своим циклом выпусков. Небольшой собственный слой покрывает потребности текущих экранов: кешированное значение по ключу, отмену, повтор временных сбоев, опрос и показ сохранённого значения.

**Решение.** Клиент использует собственный хук `useResource` в [resource.ts](../../../web/client/src/adapters/resource.ts).

| Правило | Поведение |
| --- | --- |
| Ключ и область | Чтение называется ключом с параметрами. Значения кешируются в пределах области, например сервисов сеанса или фикстуры, поэтому новый вход никогда не показывает значения другого сеанса |
| Отмена | Смена ключа или закрытие экрана отменяет чтение. Поздний ответ отменённого чтения не меняет экран |
| Повторы | Сбои сети и статусы 502, 503 и 504 повторяются дважды с растущей паузой. Отказ в запросе показывается сразу |
| Обновление и опрос | Обновление сохраняет показанное значение до прихода нового. Опрос пропускает такт, пока идёт чтение. Неизменившийся ответ сохраняет показанный объект |
| Изменения | Экран показывает значение, которое сервер вернул на сохранённое изменение, через `set`. Команды сохраняют контракт идемпотентности API |

Экран, которому нужно состояние рабочего процесса, например форма из нескольких шагов, хранит его в редьюсере рядом с экраном. Загрузка остаётся в `useResource`.

**Обоснование и последствия.** Слой не имеет зависимостей во время работы и использует существующий интерфейс `Services`, поэтому фикстура и сервер сохраняют один путь. Инвалидация между экранами, постраничные чтения и объединение одинаковых запросов не предусмотрены. Когда они понадобятся экрану, выбор TanStack Query пересматривается.

**Проверка.** Экранные тесты UI Kit покрывают состояния загрузки, сбоя и обновления на фикстуре. Сквозные сценарии проверяют те же экраны с сервером.
