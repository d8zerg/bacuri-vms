# ADR-017. Источники карт и планов

[English version](../../adr/017-map-sources.md)

**Статус** - Принято.

**Контекст.** Оператору нужна карта местности вокруг площадки и подробные планы территории и этажей. Рабочее место должно открывать их в изолированной сети.

**Решение.** В веб-клиенте использовать MapLibre GL JS для отображения данных OpenStreetMap. Пакет нужного региона готовить из выгрузки Geofabrik. Администратор импортирует пакет на площадку, а браузер получает карту и ресурсы её оформления с локального сервера. На карте показывать регион, дату исходных данных и атрибуцию OpenStreetMap с указанием лицензии ODbL. [Региональные выгрузки Geofabrik](https://download.geofabrik.de/) · [Лицензия и атрибуция OpenStreetMap](https://www.openstreetmap.org/copyright)

**Будущий настольный клиент.** Для Qt использовать MapLibre Native for Qt с C++ API и плагином Qt Location для QML. Стиль карты должен использовать возможности, поддерживаемые MapLibre GL JS и MapLibre Native. [MapLibre Native for Qt](https://github.com/maplibre/maplibre-native-qt) · [Спецификация стилей MapLibre](https://maplibre.org/maplibre-style-spec/)

**Общий контракт.** Сервер площадки по локальному HTTPS выдаёт обоим клиентам тайлы установленного региона, стиль, шрифты и значки карты, изображения планов и сведения об источнике данных. Сервер хранит идентификаторы и координаты точек наблюдения и через API выдаёт только точки, доступные пользователю. После перемещения точки оба клиента при следующем чтении получают её новое положение. Пакет карты и планы импортируются один раз на площадку.

**Ориентация камер.** Реестр камер владеет последним измерением абсолютного положения, поля зрения и состояния связи, учитывает версию конфигурации устройства и профиль ONVIF. Модуль карт через операцию реестра получает измерения видимых точек, хранит калибровку отдельно для каждого размещения и вычисляет угол сектора. Географическая карта и этажный план могут иметь разные ориентиры. Конфигурация размещения входит в резервную копию. После восстановления измерения поступают с камеры. [Сервис PTZ ONVIF](https://www.onvif.org/specs/srv/ptz/ONVIF-PTZ-Service-Spec.pdf)

**Доставка пакетов.** Модуль карт Core владеет установленными регионами, очередью загрузок и публикацией версий. Издатель независимо формирует статический HTTPS-каталог готовых растровых MBTiles и может передать те же карты в ZIP. Администратор выбирает источник, регионы и момент обновления. Для сопоставления используется устойчивый ключ региона, для выбора обновления - время исходных данных. Сервер площадки сохраняет загруженные части, проверяет SHA-256 интернет-пакета и публикует замену одного региона в транзакции. Координаты камер сохраняются отдельно. [Управление регионами](../ui.md#установка-и-обновление-регионов)

**Обновление.** Geofabrik обычно обновляет выгрузки ежедневно. На площадке изменения становятся видны после импорта нового пакета. Дату исходных данных брать из метаданных выгрузки и сохранять при импорте.

**Планы объекта.** Источником для территории служит генплан заказчика, для этажей - его поэтажные чертежи. На географической карте положение точки задаётся долготой и широтой, на локальном плане - координатами относительно изображения. Это позволяет разместить камеру на чертеже без геопривязки и открыть с обеих карт эфир или архив той же точки наблюдения.

**Геопривязка плана.** План может оставаться самостоятельным. Модуль карт хранит на плане две пары соответствующих ориентиров или одну пару с шириной изображения в метрах и азимутом его верха. Входные данные задают одно преобразование подобия в локальных координатах Web Mercator с учётом размеров растра и широты ориентира. Пропорции плана сохраняются. Опорные координаты принадлежат площадке и переживают замену офлайн-пакета региона. У планов одного здания может быть общее название для выбора этажа.

**Источник геопозиции.** Точка наблюдения имеет одно положение на обзоре территории. Источником служит ручное размещение или размещение на одном из привязанных планов. Перед изменением администратор видит наложение и выбирает источник для каждой точки с существующей геопозицией. Выбор и привязка сохраняются атомарно после проверки версии предпросмотра. Координаты и сектор от плана вычисляются при чтении с учётом поворота изображения и фактического статуса камеры. Снятие привязки сохраняет план, его размещения и исходные ручные координаты. Доступ к плану, его изображению и маркерам определяется действующими правами на точки. [Привязка плана к геокарте](../ui.md#привязка-плана-к-геокарте)

**Проверка.** При отключённом внешнем интернете открыть карту и поэтажный план, выбрать доступную точку и перейти к записи. После импорта более свежего пакета проверить отображаемую дату исходных данных и сохранение привязок камер. [Карта региона и планы](../ui.md#карта-региона-и-планы)

**Формат пакета** - растровые региональные пакеты MBTiles с PNG-тайлами 256 x 256. Сервер переводит TMS в XYZ, формирует стиль для MapLibre и отдаёт атрибуцию. Для интернет-установки сервер площадки обращается к настроенному HTTPS-каталогу. На закрытой площадке администратор переносит готовые карты с носителя. [Импорт и контракт клиентов](../ui.md#подготовка-и-импорт-региона)
