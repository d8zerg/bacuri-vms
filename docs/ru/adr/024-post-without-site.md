# ADR-024. Настольный пост при недоступной площадке

[English version](../../adr/024-post-without-site.md)

**Статус** - Принято. Аварийный эфир напрямую с камер - опция, по умолчанию выключенная.

**Контекст.** Для настольного приложения Bacuri VMS площадка - единственный источник истины: права, сеансы, запись, архив, события, тревоги, раскладки и аудит находятся на площадке, и у клиента нет собственных данных, которые считались бы истиной ([ADR-023](023-client-architecture.md)). После обрыва сети или перезапуска площадки клиент восстанавливает пост и заново проверяет права. При более долгом отказе оператор остаётся без эфира, хотя именно в этот момент он нужен охране больше всего. Пост, который продолжает работу на своей копии прав или записей, создал бы вторую истину и сохранил бы действие отозванного доступа.

**Варианты.**

| Вариант | Оценка |
| --- | --- |
| Ждать площадку | Просто и безопасно. Оператор остаётся без видео до возврата площадки |
| Переподключиться к другому узлу установки | Сохраняет все функции и проверку прав площадкой. Нужна установка из нескольких узлов |
| Аварийный эфир напрямую с камер | Эфир при отказе площадки из одного узла. Нужен доступ к камерам с поста и права, действующие без площадки |
| Локальная копия прав, записи и архива на посту | Отклонено: вторая истина, отозванный доступ продолжает действовать, запись на посту выходит за гарантии архива |
| Стена собирается на сервере и передаётся тонким постам | Отклонено: выше задержка PTZ и перемотки, GPU на сервере для каждого поста, перегрузка сервера ухудшает все посты сразу |

**Решение.** Основной путь - переподключение к другому узлу. Аварийный эфир - опция, которую администратор включает явно.

| Часть | Решение |
| --- | --- |
| Адреса установки | Ответ сеанса перечисляет клиентские адреса всех узлов установки, сеанс действителен на каждом из них. После потери связи клиент пробует текущий узел, затем остальные и восстанавливает пост так же, как после перезапуска: раскладки, тревоги, позицию архива и фокус с повторной проверкой прав. Пост показывает отказ и используемый узел |
| Включение аварийного режима | По умолчанию выключен. Администратор включает его для площадки, для указанных постов и для групп камер по ролям |
| Аварийный допуск | Пока связь есть, площадка выдаёт посту допуск для вошедшего пользователя. Допуск подписан площадкой и привязан к ключу поста в хранилище ключей ОС. Срок действия задаёт администратор, не больше 12 часов, клиент продлевает допуск, пока есть связь. Допуск перечисляет камеры и профили, которые пользователь может смотреть в эфире, их маски приватности и право на звук |
| Доступ к камерам | Для аварийного режима площадка создаёт на каждой камере отдельную учётную запись только для просмотра и передаёт её данные в допуске, зашифрованными для ключа поста. Учётные данные администратора камеры на пост не попадают. Камера без отдельной учётной записи для просмотра в допуск не входит |
| Вход в режим | Режим предлагается, когда площадка и все узлы недоступны 30 с, и начинается после подтверждения оператором. Новый вход без площадки невозможен |
| Работа в режиме | Только эфир камер из допуска. Клиент накладывает маски приватности до отрисовки первого кадра, камера, маску которой клиент не может наложить, не показывается. Архив, запись, PTZ, экспорт и обработка тревог недоступны. Постоянная плашка сообщает, что площадка недоступна и Bacuri VMS не ведёт запись |
| Журнал | Каждый просмотр записывается в локальный журнал только для добавления, связанный цепочкой хешей и подписанный ключом поста. После возврата площадки клиент передаёт журнал в аудит площадки, площадка проверяет цепочку |
| Выход из режима | Когда возвращается площадка или узел, клиент закрывает прямые потоки и возвращается на путь площадки с повторной проверкой прав. Допуск заканчивается по сроку, при выходе пользователя или по отзыву, который площадка передаёт после возврата. Отзыв поста или пользователя меняет учётные записи для просмотра на камерах |

**Обоснование и последствия.** Переподключение к другому узлу сохраняет один источник истины и все функции и опирается на резервирование установки. Аварийный режим закрывает площадку из одного узла и не делает пост вторым источником истины: он показывает только эфир по правам, выданным площадкой заранее, а его использование учитывается в аудите площадки. Отзыв во время отказа не доходит до поста, поэтому срок допуска ограничивает время, в течение которого отозванный пользователь ещё может смотреть, и администратор выбирает срок с учётом этого. Учётные записи для просмотра добавляют площадке задачу настройки камер и проверку возможности камеры. Видео периода отказа попадает в архив, только если камера пишет на свой носитель и площадка потом догружает запись. **Проверка.** Сценарии `workstation-site-failover` и `workstation-emergency-live` реестра паритета. Остановка активного узла переводит пост на другой узел в пределах бюджета переключения установки плюс 5 с с повторной проверкой прав. Остановка всех узлов при выключенном режиме показывает только отказ. При включённом режиме камеры из допуска показывают эфир с масками, другие функции недоступны, после возврата площадка принимает журнал. Истёкший допуск, отозванный пост, камера без учётной записи для просмотра и маска, которую клиент не может наложить, каждая оставляют камеру скрытой.
