# ADR-020. Каталог ошибок и локализованные сообщения о сбоях

[English version](../../adr/020-error-catalog.md)

**Статус** - Принято.

**Контекст.** HTTP API возвращал код Problem, выбранный в каждом месте сервера, а HTTP-статус записывался рядом, поэтому один код встречался с разными статусами. Служебный gRPC описывал сбои английским текстом. Веб-клиент сопоставлял коды с сообщениями отдельно на каждом экране. Часть текстов формировал сервер на русском языке: страницу неудачного корпоративного входа и описания изменений политики записи в журнале событий. У причины не было класса, рекомендуемой обработки и места в справочнике.

**Решение.** Один каталог [errors.yaml](../../../contracts/v1/errors.yaml) называет каждую причину сбоя. Код имеет категорию, один HTTP-статус, один код статуса gRPC, класс повтора, адресата и описание на английском языке. Всё остальное выводится из каталога.

| Потребитель | Что получает |
| --- | --- |
| Сервер | Тип `ErrorCode` со свойствами каждого кода, сформированный при сборке. Сбой несёт код и параметры, HTTP-статус и статус gRPC следуют из кода |
| HTTP API | Поле `code` ответа Problem. Схема Problem перечисляет публичные коды HTTP из каталога |
| Служебный gRPC | Код статуса из каталога и код как сообщение статуса |
| Веб-клиент | Свойства каждого кода и сообщение `error.<code>` на каждом языке интерфейса. Экран может показать собственную формулировку для причины, которую он объясняет в своём контексте |
| Справочник | [Справочник ошибок](../errors.md) на английском и русском языках, сформированный из каталога и сообщений клиента |

Каталог задаёт, где может появиться каждая причина. Обработчик HTTP передаёт публичный код gRPC при совпадении имени причины и числового статуса. Для внутренней причины или ошибки транспорта обработчик выбирает публичный код операции. В OpenAPI перечислены коды состояний источников и заданий установки карт. При повторе чтения клиент учитывает класс повтора.

Сервер HTTPS возвращает Problem при превышении лимита тела или заголовков, неподдерживаемом значении Expect и ошибке разбора HTTP. Идентификатор запроса содержится в теле и заголовке ответа. При потере соединения с базой сервер возвращает `dependency_unavailable` (503), при непредвиденной ошибке обработчика - `internal_error` (500).

Сервер не отправляет текст, предназначенный людям. Страница или запись журнала, которой нужны слова, несёт код и параметры, а клиент выводит их на языке интерфейса.

| Класс повтора | Значение для вызывающей стороны |
| --- | --- |
| `never` | Запрос нужно изменить |
| `after_change` | Состояние изменилось: прочитать его снова и решить снова |
| `later` | Временная причина: клиент может повторить после паузы |
| `user_action` | Человеку нужно войти, подтвердить или выполнить шаг |

**Обоснование и последствия.** Новая причина добавляется в одном месте, и проверка называет каждого потребителя, у которого её ещё нет. Категории и классы повтора задают обработку по умолчанию для причин, которые экран не знает. Каталог служит основой справки и последующей диагностики площадки, например подсчёта сбоев по категориям. Изменение HTTP-статуса кода меняет контракт API и следует его правилам совместимости.

**Проверка.** `task api:check` сравнивает каталог с кодами Problem и состояний карт в контракте, кодами в исходниках сервера, сообщениями обоих языков клиента и справочником ошибок. Проверка типов клиента отклоняет код без сообщения.
