# ADR-021. Размещение видеоаналитики

[English version](../../adr/021-video-analytics.md)

**Статус** - Принято.

**Контекст.** Площадка обнаруживает движение внутри рекордера: декодирует поток до изображения 64×48 в оттенках серого и сравнивает соседние кадры. Результат формирует тревоги и поиск движения в архиве. Дальнейший анализ требует сопровождения объектов, линий и зон с направлением, контроля саботажа камеры, классов объектов и автоматического обезличивания выданных копий. Такой анализ может выполняться на сервере, в веб- или настольном клиенте либо в камере. Выбор определяет, существуют ли тревоги при закрытых клиентах, видят ли два поста одни и те же события и какую нагрузку несут рекордер и рабочая станция оператора.

**Варианты.**

| Вариант | Оценка |
| --- | --- |
| Анализ в клиенте | События существуют, только пока клиент показывает камеру. Два поста вычисляют разные результаты. Тревоги, индекс архива и аудит не могут на них опираться. Рабочая станция тратит GPU на анализ вместо показа видео |
| Анализ в процессе рекордера | Один процесс снова владеет записью и неограниченной вычислительной нагрузкой. Сбой или медленная модель может задержать запись блоков. Рекордер не масштабирует анализ отдельно |
| Анализ только в камере | Возможности зависят от модели и прошивки. Результаты не имеют общей схемы и не повторяются на архиве |
| Отдельный серверный сервис аналитики | События и метаданные существуют без клиентов и одинаковы для всех потребителей. Запись изолирована от анализа. Анализ масштабируется по узлам и повторяется на архиве |

**Решение.** Видеоаналитика - отдельный серверный сервис `bacuri-analytics` на C++23 с OpenCV 5. Он работает на узле записи или на отдельном узле анализа той же площадки.

| Часть | Правило |
| --- | --- |
| Вход | Подписка на поток рекордера, по умолчанию дополнительный профиль, с аппаратным декодированием, где оно есть на узле. Для повторного анализа или проверки правила сервис читает архив той же точки |
| Анализаторы | Каждый анализатор объявляет имя, версию, входной профиль, частоту кадров, схему настроек и стоимость ресурсов. Классические анализаторы используют модули обработки изображений и видео OpenCV. Модели выполняются через модуль DNN OpenCV из файлов ONNX, закреплённых по хешу в поставке |
| Выход | Наблюдения передаются ядру через `SubmitObservation` с точкой, ревизией привязки, версией правила и временем источника. Метаданные пишутся в индекс анализа: треки, классы объектов, сетка движения, уровень активности и состояние камеры. Каждая запись содержит время UTC и PTS кадра и версию анализатора |
| Тревоги | Ядро формирует тревоги из наблюдений, как сейчас. Сервис ничего не показывает людям и не передаёт текст для людей: причины - коды каталога ошибок |
| Клиенты | Веб- и настольный клиенты читают метаданные через публичный API и показывают их поверх кадра: уголки трека, короткий след, зоны правил и полосу активности на шкале. Клиент не вычисляет событий и индекса. Обработка только для показа, например развёртка изображения fisheye, не меняет архив и выданную копию |
| Камеры | События и метаданные камеры, включая поток метаданных ONVIF, приводятся к той же схеме с камерой в качестве источника |
| Приватность | Лица обнаруживаются только для их маскирования. Идентификация людей по биометрическим признакам не входит в продукт. Метаданные следуют правам, маскам и сроку хранения видео той же точки |
| Отказ | Остановленный или перегруженный сервис не останавливает запись и эфир. Точка показывает недоступность анализа, архив сохраняет пропуск в индексе анализа, повторный анализ может его заполнить |

**Обоснование и последствия.** Серверное размещение сохраняет один результат для тревог, поиска, экспорта и аудита и позволяет анализу работать круглосуточно без операторов. Рекордер теряет детектор и сохраняет только запись. Новый анализатор добавляется в сервис без изменения клиентов, которые читают общую схему метаданных. Сервису нужен собственный бюджет ресурсов на узле, квалификация указывает поддерживаемое число потоков для каждого анализатора и профиля узла. Поставка несёт модели с лицензиями и хешами и работает без доступа к сети. OpenCV следует правилам жизненного цикла технологий: закреплённая поддерживаемая ветка и контролируемый перенос исправлений. [Жизненный цикл технологий](015-technology-lifecycle.md) · [Автономная поставка](011-offline-delivery.md) · [Модель времени](004-time.md)

**Проверка.** Размеченный видеонабор с дневными, ночными, инфракрасными и погодными сценами даёт точность и полноту по каждому анализатору и долю ложных тревог на камеро-час. Повторный анализ того же архива даёт те же наблюдения и метаданные. Время от кадра до наблюдения и до тревоги на посту измеряется по p95 при профиле нагрузки узла. Остановка сервиса сохраняет запись и эфир, состояние точки показывает недоступность анализа.
