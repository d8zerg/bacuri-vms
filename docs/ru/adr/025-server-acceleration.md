# ADR-025. Выбор ускорения для серверных задач

[English version](../../adr/025-server-acceleration.md)

**Статус** - Принято.

**Контекст.** У узла площадки может не быть GPU, может быть GPU NVIDIA с NVDEC и NVENC, GPU Intel или AMD с VA-API или ускоритель вывода нейросетей через CUDA или OpenVINO. Запись сохраняет поток камеры без перекодирования, и декодирование ей не нужно. Другие задачи декодируют, рисуют или кодируют видео: маски приватности в эфире, профили эфира для веб-, мобильных клиентов и стены, экспорт, опорные кадры и миниатюры, анализ из [ADR-021](021-video-analytics.md). Потребительские GPU ограничивают число сессий кодера, а видеопамять общая для всех задач узла. Жёсткий выбор ускорителя либо оставляет GPU без дела, либо позволяет фоновой задаче забрать кодер у живого просмотра.

**Варианты.**

| Вариант | Оценка |
| --- | --- |
| Всё на CPU | Предсказуемо, но маски, перекодирование и анализ многих камер требуют в несколько раз больше ядер |
| Один переключатель на узел | Просто, но либо все задачи уходят на CPU, когда GPU занят, либо фоновая задача конкурирует с живым просмотром |
| Автоматический выбор для каждой задачи по бюджету устройства | Задача использует GPU, пока свободна её доля бюджета, иначе переходит на CPU. Нужны проверка устройства, бюджет и видимая причина каждого выбора |
| Выбор для каждой задачи администратором | Администратор решает, какие задачи используют GPU, по измеренному бюджету. Нужны та же проверка и переход на CPU, когда бюджета или устройства не хватает |

**Решение.** Ускорение задаётся для каждого узла в одном из трёх режимов. После развёртывания узел вычисляет только на CPU. Администратор переводит узел в ручной или автоматический режим после проверки устройства.

| Часть | Решение |
| --- | --- |
| Режимы | Только CPU: все задачи на CPU, режим по умолчанию после развёртывания. Вручную: администратор выбирает задачи, которые используют GPU, остальные работают на CPU. Авто: узел сам выбирает задачи по бюджету и приоритетам |
| Проверка | Фоновая проверка запускается, когда администратор выходит из режима «Только CPU», при запуске узла, после смены устройства или драйвера и по запросу. Она определяет декодеры и кодеры (NVDEC, NVENC, VA-API), бэкенды вывода (CUDA, OpenVINO, CPU), объём видеопамяти и лимит сессий кодера и измеряет бюджет короткими пробами декодирования, кодирования и вывода. Проверка показывает этапы и ход выполнения и может быть отменена. Пока новый режим не применён, узел работает в прежнем. Результат хранится с устройством, драйвером и временем проверки |
| Форма настройки | Одна форма для обоих режимов с GPU: каждый вид задач со стоимостью, устройством, долей бюджета и ожидаемым состоянием. В ручном режиме администратор выбирает задачи и видит, укладывается ли выбор в бюджет. В режиме «Авто» форма только для чтения и показывает выбор узла и его причину |
| Бюджет | Каждый вид задач объявляет свою стоимость: сессии декодера и кодера, видеопамять и время GPU. Узел выдаёт задаче ускоритель, пока бюджет устройства это позволяет, иначе задача работает на CPU |
| Приоритеты | Сначала эфир с масками и профили эфира, затем живой анализ, затем экспорт, задания анализа архива, опорные кадры и миниатюры. Задача с меньшим приоритетом освобождает устройство, когда оно нужно задаче с большим приоритетом, и продолжает на CPU или ждёт в своей очереди |
| Отказ | В ручном и автоматическом режимах GPU никогда не становится точкой отказа. При отказе устройства, сбросе драйвера или превышении бюджета выбранными задачами затронутые задачи продолжаются на CPU, администратор получает предупреждение с причиной. После успешной проверки узел возвращает их на GPU. Эфир и запись не останавливаются. Выбор, который не укладывается в бюджет, виден в форме до применения |
| Видимость | Состояние узла, метрики и диагностика каждой задачи показывают выбранный путь, устройство и причину перехода на CPU |

| Задача | Ускорение |
| --- | --- |
| Запись и архив | Нет: поток пишется без перекодирования |
| Маски приватности в эфире | Декодирование, наложение масок и кодирование на GPU: самая дорогая живая задача |
| Профили эфира для веб-, мобильных клиентов и стены | Кодирование через NVENC или VA-API |
| Экспорт с масками или в другой формат | GPU, когда он свободен: фоновая задача может ждать в очереди |
| Опорные кадры и миниатюры для быстрой перемотки | NVDEC или VA-API для множества коротких декодирований |
| Живой анализ | Аппаратное декодирование, вывод DNN на CUDA или OpenVINO. Классические анализаторы OpenCV, например движение по субпотоку, остаются на CPU, где они дешевле |
| Задания анализа архива и синопсис | GPU с низким приоритетом, не забирая устройство у живых задач |
| Метаданные, события и API | CPU |

**Анализ на разных бэкендах.** Вывод на CUDA, OpenVINO и CPU может давать немного разные результаты. Поэтому каждое наблюдение записывает анализатор, модель и бэкенд, а повторный анализ из [ADR-021](021-video-analytics.md) даёт тот же результат на том же бэкенде. Точность и полнота модели измеряются и заявляются для каждого бэкенда, бэкенд без измеренных результатов для этой модели не используется.

**Обоснование и последствия.** Выбор для каждой задачи использует GPU там, где он даёт наибольшую экономию, и ставит живой просмотр впереди фоновой работы. Режим «Только CPU» по умолчанию делает новую установку предсказуемой на любом оборудовании, а режим с GPU выбирается только по результату измеренной проверки. Цена - проверка устройства, бюджет на устройство и планировщик, переносящий задачи между GPU и CPU, а также квалификация каждой модели на каждом бэкенде. Клиент следует тому же принципу на рабочем месте ([ADR-022](022-desktop-video-path.md)). [Размещение видеоаналитики](021-video-analytics.md) · [Медиа](005-media.md)

**Проверка.** Новый узел вычисляет только на CPU. Выход из этого режима запускает проверку с видимыми этапами, её отмена сохраняет прежний режим. На узлах без GPU, с NVIDIA и с VA-API проверка показывает устройства и измеренный бюджет. В ручном режиме GPU используют только выбранные задачи, в режиме «Авто» форма только для чтения совпадает с фактическими путями задач. При полной нагрузке масками в эфире задание экспорта работает на CPU или ждёт и не снижает частоту кадров живого просмотра. Сброс GPU во время работы в любом режиме с GPU переводит задачи на CPU без остановки эфира и записи, предупреждает администратора и возвращает задачи после проверки. Каждое наблюдение называет свой бэкенд, повторный анализ на том же бэкенде даёт тот же результат.
