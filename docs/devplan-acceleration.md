# План разработки ускорения серверных задач Bacuri VMS

**Статус плана** - Готово к приёмке.

Цель - вычисления узла площадки на GPU там, где это даёт наибольшую экономию, без превращения GPU в точку отказа. После развёртывания узел работает только на CPU. Администратор переводит узел в ручной или автоматический режим по результату фоновой проверки устройства и видит, какие задачи используют GPU и почему. Решение - [ADR-025](adr/025-server-acceleration.md).

## Состав и связь с платформой

| Область | Результат для пользователя | Шаги плана | Шаги платформы |
| --- | --- | --- | --- |
| Проверка устройства | Список декодеров, кодеров и бэкендов вывода узла и измеренный бюджет GPU с ходом проверки по этапам | 1.1 | 6.1 |
| Режимы и настройка | Режимы «Только CPU», «Вручную» и «Авто» для каждого узла, одна форма задач с бюджетом, в режиме «Авто» только для чтения | 1.2, 2.1 | 9.1 |
| Планирование | Приоритет эфира и масок над анализом и фоновыми задачами, переход на CPU при нехватке бюджета и отказе устройства | 1.3 | 3.3, 5.1 |
| Задачи узла | Маски приватности и профили эфира, экспорт, опорные кадры и миниатюры, живой анализ и задания анализа архива на выбранном устройстве | 2.2 | 7.4, 9.4, 10.4, 10.5, аналитика 1.4 |

Запись сохраняет поток камеры без перекодирования и в планировании ускорения не участвует. Клиенты читают состояние и настройку ускорения через публичный API, права на изменение - у администратора площадки.

## Принципы

| Принцип | Правило |
| --- | --- |
| Предсказуемость по умолчанию | Новый узел вычисляет только на CPU на любом оборудовании. Режим с GPU включает администратор |
| Решение по измерению | Режим с GPU применяется только после проверки, которая измерила бюджет устройства на этом узле с этим драйвером |
| GPU не точка отказа | В режимах «Вручную» и «Авто» отказ устройства, сброс драйвера или нехватка бюджета переводят задачи на CPU с предупреждением. Эфир и запись не останавливаются |
| Живое впереди фонового | Эфир с масками и профили эфира, затем живой анализ, затем экспорт, задания, опорные кадры и миниатюры |
| Видимость | Для каждой задачи видны режим, устройство, доля бюджета и причина перехода на CPU |

## Этап 0. Зафиксировать задачи и стоимость

### Шаг 0.1. Реестр задач и стоимости

Составить реестр видов задач, которые могут использовать GPU: маски приватности в эфире, профили эфира для веб-, мобильных клиентов и стены, экспорт с масками или в другой формат, опорные кадры и миниатюры, живой анализ и задания анализа архива. Для каждого вида указать единицу работы (поток, кадр, задание), стоимость на GPU (сессии декодера и кодера, видеопамять, время GPU) и на CPU (ядра, память), приоритет и поведение при вытеснении: продолжить на CPU или ждать в очереди.

**Приёмка**

Каждый вид задач связан со своим шагом платформы или аналитики и с методикой измерения стоимости. Стоимость указана для профилей H.264 и H.265 Main в разрешениях 1080p и 2K при 25 к/с.

**Результат** - Готово к приёмке. [Реестр задач и методика измерения](ru/server-acceleration-costs.md) связывают каждый вид задач с единицей работы, приоритетом, действием при вытеснении и стоимостью. На эталонном узле выполнены 64 прогона: восемь операций, четыре входных профиля, два способа выполнения (CPU и NVIDIA). В реестре 2K обозначает 2560x1440. Для анализа измерена базовая стоимость декодирования и расчёта движения. Стоимость вывода модели добавляется по результатам замера конкретной модели и бэкенда.

## Этап 1. Проверка, режимы и планировщик

### Шаг 1.1. Фоновая проверка устройства

Реализовать проверку на C++23 как фоновую операцию узла. Этапы: перечисление устройств и драйверов, декодеры NVDEC и VA-API, кодеры NVENC и VA-API с лимитом сессий, бэкенды вывода CUDA, OpenVINO и CPU, объём видеопамяти, короткие пробы декодирования, кодирования и вывода на эталонном кадре для каждого вида задач. Проверка запускается при выходе из режима «Только CPU», при запуске узла, после смены устройства или драйвера и по запросу администратора. Публичный API запускает проверку, показывает этапы, ход выполнения и результат и отменяет её. Пробы ограничены по времени и не забирают устройство у работающих задач. Результат хранится с моделью устройства, версией драйвера и временем проверки.

**Приёмка**

На узлах без GPU, с NVIDIA и с VA-API проверка показывает устройства, лимиты и измеренный бюджет, повторная проверка на том же узле даёт бюджет в пределах заявленного разброса. Отмена в любом этапе сохраняет прежний режим. Во время проверки эфир и запись не теряют кадров. Смена драйвера помечает прежний результат как устаревший.

**Результат** - Готово к приёмке. [Фоновая проверка узла](ru/server-acceleration-costs.md#фоновая-проверка-узла) доступна через API администратора. Повторные проверки на CPU и GeForce RTX 4070 Ti дали одинаковый бюджет кодеков. Проверены NVDEC, NVENC, контрольный вывод на CPU, CUDA и OpenVINO CPU, отмена на каждом этапе и восстановление результата после перезапуска. Во время проверки на стенде счётчики потерь WebRTC не выросли, архивные блоки содержали все 25 кадров. Смена отпечатка драйвера проверена автоматическим тестом. Для завершения аппаратной приёмки нужен повторный прогон на узле с работающим VA-API.

### Шаг 1.2. Режимы и настройка узла

Хранить для каждого узла режим «Только CPU», «Вручную» или «Авто» и в ручном режиме - набор задач на GPU. Новый узел получает «Только CPU». Применение режима с GPU требует действующего результата проверки. Перед применением сервер сравнивает ручной выбор с бюджетом и возвращает задачи, которые не укладываются. В режиме «Авто» сервер возвращает свой выбор и причину для каждой задачи, изменить его нельзя. Изменение режима записывается в аудит, ошибки возвращают коды каталога ошибок. Описания операций OpenAPI - только на английском.

**Приёмка**

Новый узел работает на CPU. Применение режима с GPU без проверки или с устаревшей проверкой отклоняется с кодом причины. Ручной выбор сверх бюджета виден до применения. Без права администратора площадки режим не меняется. Каждое изменение есть в аудите с прежним и новым значением.

**Результат** - Готово к приёмке. [Настройка ускорения узла](ru/server-acceleration-costs.md#настройка-ускорения-узла) хранит режим и ручной выбор. API предоставляет предпросмотр с бюджетом, причинами и задачами сверх лимита. Применение повторяет проверку, защищено ревизией и записывает прежние и новые значения в журнал площадки. Проверены CPU и NVIDIA, отсутствие и устаревание замера, возврат на CPU при отключённом медиасервисе, права доступа и конкурентная запись.

### Шаг 1.3. Планировщик и переход на CPU

Реализовать планировщик устройства узла: выдача GPU задаче в пределах бюджета, приоритеты, вытеснение задачи с меньшим приоритетом на CPU или в очередь, возврат на GPU при освобождении бюджета. В ручном режиме GPU получают только выбранные задачи, в режиме «Авто» - задачи по приоритету и стоимости. При отказе устройства, сбросе драйвера или ошибке кодера задачи переходят на CPU, администратор получает предупреждение, после успешной проверки задачи возвращаются. Метрики показывают занятость сессий, видеопамяти и времени GPU, число задач на GPU и на CPU и переходы с причиной.

**Приёмка**

При полной нагрузке масками в эфире экспорт и задания уходят на CPU или ждут, частота кадров эфира не снижается. Исчерпание сессий NVENC на потребительском GPU переводит на CPU задачи с меньшим приоритетом, а не новый эфир. Сброс GPU во время работы не останавливает эфир и запись, переход и возврат видны в метриках и журнале. Задача не переключается между устройствами чаще заданного предела.

**Результат** - Готово к приёмке. [Планировщик узла](ru/server-acceleration-costs.md#планирование-работающих-задач) выдаёт разрешения экземплярам задач, учитывает сессии кодера, видеопамять и время GPU, отзывает разрешения при вытеснении и проверяет устройство перед возвратом. На стенде RTX 4070 Ti два потока с масками при 25 кадрах/с заняли бюджет, экспорт продолжился на CPU. При фактическом отказе в 13-й сессии NVENC экспорт освободил кодер для нового эфира. При имитации сообщения исполнителя о сбросе драйвера записаны 42 последовательных сегмента и обработаны 1050 из 1050 кадров с переходом GPU -> CPU -> GPU. Предупреждения доступны администратору узла, переходы отражаются в журнале и метриках. Подключение продуктовых конвейеров предусмотрено в шаге 2.2.

## Этап 2. Интерфейс и задачи узла

### Шаг 2.1. Настройка ускорения в веб- и настольном клиенте

В разделе узла показать выбор режима: «Только CPU», «Вручную», «Авто». При выходе из «Только CPU» запустить проверку и показать её ход: этапы с состоянием, индикатор выполнения текущего этапа и кнопку отмены. Остальная настройка узла остаётся доступной. После проверки показать устройства и форму задач: вид задачи, стоимость, устройство, доля бюджета и ожидаемое состояние. В режиме «Вручную» задачи выбираются флажками, форма показывает остаток бюджета и задачи, которые не укладываются. В режиме «Авто» форма только для чтения и показывает выбор узла и причину. В состоянии узла видны предупреждения о переходе на CPU и кнопка «Проверить снова». Тексты на русском и английском, клавиатурный доступ и подписи для средств доступности. Настольный клиент получает сценарий в реестре паритета.

**Приёмка**

Снимки экрана формы в обеих темах и на обоих языках для режимов «Вручную» и «Авто», для хода проверки, её отмены и ошибки. Индикатор хода отключается при выключенном движении. Форма в режиме «Авто» совпадает с фактическими путями задач узла.

### Шаг 2.2. Задачи узла на выбранном устройстве

Подключить к планировщику маски приватности и профили эфира (шаг VMS 9.4), экспорт (7.4, 10.5), опорные кадры и миниатюры (10.4), живой анализ и задания анализа архива (шаг аналитики 1.4). Каждая задача запрашивает устройство у планировщика, сообщает фактический путь и умеет продолжить работу на CPU без потери кадров эфира и с продолжением задания с последней точки. Наблюдения аналитики записывают бэкенд.

**Приёмка**

Для каждого вида задач результат на GPU и на CPU совпадает: кадры эфира и экспорта с масками, опорные кадры по номерам, наблюдения на одном бэкенде. Перевод задачи на CPU во время работы не создаёт разрыва эфира и повторного начала задания.

## Этап 3. Квалифицировать ускорение

### Шаг 3.1. Плотность, отказы и долгая работа

На профилях узла без GPU, с потребительским и серверным GPU NVIDIA и с VA-API измерить плотность эфира с масками, число перекодируемых профилей, скорость экспорта и анализа в каждом режиме. Сбросить драйвер, отключить устройство, исчерпать видеопамять и сессии кодера во время работы. Прогнать 72 часа в режиме «Авто» со сменой нагрузки.

**Приёмка**

Для каждого профиля узла указаны плотность и скорость на GPU и на CPU и бюджет проверки. Отказы не останавливают эфир и запись. Рост памяти и видеопамяти за 72 часа не превышает предела паспорта узла, число переключений устройства в пределах заданного.

## Порядок выполнения

Начать с реестра 0.1: без стоимости задач бюджет не проверяется. Проверка 1.1 и режимы 1.2 открывают интерфейс 2.1, планировщик 1.3 - подключение задач 2.2. Задачи подключаются по мере готовности своих шагов платформы и аналитики, до этого они работают на CPU. Квалификация 3.1 подтверждает числа для паспортов узлов.
