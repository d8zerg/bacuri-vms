# Паспорт стенда Bacuri VMS PoC

**Статус** - Принято. [План разработки, шаг 0.1](devplan-poc.md#шаг-01-границы-poc-и-проверяемые-решения)

## Окружение

| Параметр | Профиль первого прогона |
| --- | --- |
| Узел | Один Linux x86-64, Intel Core i7-13700H, 20 логических CPU, 15 ГиБ доступной системе RAM. Дистрибутив в контейнерах - Debian 13 |
| Хранилище | ext4 на NVMe на опорном узле. Постоянные тома PostgreSQL и архива разделены. Для воспроизводимой проверки заполнения выделен отдельный tmpfs объёмом 64 МиБ |
| Сеть | Изолированная сеть проекта Docker Compose. На хосте тестовая камера доступна через loopback. Для прогона с физической камерой фиксируются сегмент сети, RTT и пропускная способность |
| Браузеры | Google Chrome и Firefox на Linux. Точные версии и совместимость H.264 фиксируются в протоколе браузерной проверки |
| Синтетическая камера | RTSP/TCP, H.264, основной профиль 1280×720, 25 кадров/с, целевой битрейт 2 Мбит/с. Дополнительный 640×360, 15 кадров/с, целевой битрейт 0,5 Мбит/с. Ключевой кадр запрашивается не реже одного раза в секунду, в кадре видна отметка времени конвейера |
| Физическая камера | Требуется одна камера с двумя одновременно доступными H.264-профилями. Модель, прошивка, разрешения, фактические битрейты и GOP вносятся при подключении. Учётные данные хранятся вне паспорта |

Синтетическая камера используется для воспроизводимой проверки двух потоков. Физический прогон подтверждает совместимость конкретного устройства. Профиль компактного аппаратного узла проверяется отдельно по фактическому потреблению ресурсов.

## Результаты проверки инфраструктуры

С чистой копии источников прошли сборки GCC 14.2 и Clang 19.1, CTest, ASan/UBSan для стартовой команды ядра и статический анализ. PostgreSQL 17.11 ответил на запрос по сети Compose. Оба H.264-профиля синтетической камеры декодировались в ожидаемом разрешении. После остановки и повторного запуска тестовые данные PostgreSQL и архива сохранились. Заполнение tmpfs вернуло `ENOSPC` на границе 64 МиБ.

## Протокол измерений

Функциональный прогон использует одну физическую и одну синтетическую камеру. Для смешанного профиля предусмотрены восемь двухпоточных источников с основным потоком номинально 2 и 4 Мбит/с в отдельных прогонах. Для каждого режима предусмотрены 5 минут прогрева и 30 минут измерений. Во время прогона одновременно работают запись, один клиент эфира, один клиент архива, поиск и тестовые наблюдения с частотой 1 событие/с. Для первого кадра, окна поиска и задержки тревоги собирается не менее 200 проб на режим. Холодный поиск прогоняется отдельно с описанием начального состояния кэша.

Основные условия приёмки приведены в матрице. Ориентир для планирования Basic - до 2 с по p95 для первого кадра эфира, отображения тревоги и первой страницы поиска. В каждом прогоне фиксируются p50, p95, p99, число проб, доля ошибок, потребление ресурсов, глубина очередей, разрывы и объём записи на диске. Стоимость хранения рассчитывается из фактического объёма за единицу времени и ёмкости выбранного носителя. Для каждого сценария отказа фиксируются начало отказа, первый обнаруженный пропуск, момент возвращения проверенной операции и объём невосстановимых данных.

| Поле результата | Что записать |
| --- | --- |
| Воспроизводимость | Ревизия проекта, версии образов и пакетов, оборудование, тип файловой системы, конфигурация сети и источник |
| Нагрузка | Число потоков и клиентов, измеренный битрейт, GOP, частота событий, длительность, объём выборки и условия запуска |
| Наблюдение | Ожидаемый результат, фактический результат, метрики и ссылки на артефакты |
| Сбои | Причина, диапазон пропуска, проверенные копии, потеря данных, длительность восстановления записи, архива и конфигурации |
