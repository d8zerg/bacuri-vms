# Прототип интерфейса Bacuri VMS PoC

**Статус** - Принято. [План разработки, шаг 0.2](devplan-poc.md#шаг-02-интерактивный-прототип-и-визуальная-система)

Запуск - `task prototype:up`. Адрес по умолчанию - [http://127.0.0.1:8088](http://127.0.0.1:8088). Для остановки используется `task prototype:down`.

Адреса RTSP проверяются по тестовому набору. Эфир и архив воспроизводят локальные фрагменты WebM. Проверка связи, появление записи, тревоги и отказы моделируются в браузере. Перезагрузка возвращает начальные условия для следующего участника. Разделы «Мониторинг» и «Камеры» переключают роль оператора и монтажника.

## Визуальная система

| Компонент | Правило |
| --- | --- |
| Рабочее пространство | Тёмные нейтральные поверхности отделяют кадр, навигацию и ленту. На широком экране видео и тревоги находятся рядом, на узком лента следует после шкалы |
| Цвет и типографика | Токены заданы в `:root` файла [styles.css](../prototype/dist/styles.css). Мятный обозначает основное действие или подтверждённый статус, янтарный - ожидание или неопределённость, розовый - ошибку. Время и счётчики используют моноширинные цифры |
| Форма камеры | Явные подписи, раздельные адреса и подсказки по их назначению. Исправимая ошибка фокусирует поле, значения открытой формы сохраняются |
| Результат проверки | Связь, основной поток, дополнительный поток, запись и воспроизведение имеют отдельные состояния. Доступность камеры и успешное чтение кадра проверяются как разные действия |
| Шкала архива | Сплошная заливка для записи, серая штриховка для пропуска, янтарная для оценочного времени, точечная для каталогизации. Легенда, текст состояния и выделенная позиция дополняют цвет |
| Тревога | Карточка показывает приоритет, время и точку. Открытие архива переводит фокус в область видео, возврат переводит фокус на выбранную карточку |
| Сбой | Сообщение показывает причину и доступное действие. Обрыв связи останавливает воспроизведение. После повторного подключения сохраняются выбранная тревога и интервал |
| Клавиатура | Tab и Shift+Tab перемещают фокус, Enter и Space активируют кнопки. На шкале клавиши со стрелками меняют позицию, Home и End выбирают границы. Видимый фокус обозначен обводкой |

После проверки потоков фокус переходит к созданию записи. По завершении записи он переходит к открытию фрагмента. После первого воспроизводимого кадра доступно подтверждение. Асинхронный шаг переводит фокус только если он оставался на исходной кнопке.

## Задания для проверки

Открыть свежую вкладку для каждого участника. Зачитать цель задания и дать тестовые данные. Наблюдать действия без подсказок, записывать запросы на помощь и причины остановки. Если помощь необходима, пометить прогон и повторить маршрут после исправления.

| Роль | Задание и начальные условия | Наблюдаемый результат |
| --- | --- | --- |
| Монтажник | Открыть «Камеры». Подключить «Погрузочные ворота 02» с адресами `rtsp://127.0.0.1:8554/main` и `rtsp://127.0.0.1:8554/sub`. Убедиться, что запись можно воспроизвести | Видны два проверенных профиля. Созданный фрагмент открывается и воспроизводится. Участник подтверждает кадр, результат отмечен в форме |
| Монтажник | Установить «Обрыв связи» и проверить те же адреса. После ошибки восстановить тестовую связь и закончить ввод камеры | Участник называет причину отказа, повторяет проверку, введённые значения сохранены. После появления «Камера доступна» участник ещё проверяет запись |
| Оператор | В «Мониторинге» открыть тревогу «Движение у ворот», посмотреть запись и вернуться к тревоге | Открывается интервал с отметки 14:21:22. Точка видна. Фокус при возврате попадает в выбранную карточку |
| Оператор | Открыть «Потеря видеопотока» и объяснить состояние записи на 14:22:12 | Видны границы пропуска и его причина. Участник определяет, что в выбранном интервале запись отсутствует |
| Оператор | Открыть «Смещение часов камеры», затем «Поток восстановлен». Какое видео доступно в каждый момент? | Первый фрагмент доступен с пометкой ±8 с. Для второго отображается каталогизация и повторная проверка открывает запись |
| Оператор | Во время просмотра выбрать «Обрыв связи» и вернуться к фрагменту | Связь и архивный пропуск отображаются разными сообщениями. После подключения сохраняются выбранная тревога и позиция |
| Обе роли | Повторить основной маршрут с клавиатуры | Все действия доступны. Фокус приходит в ожидаемую область после ошибки, открытия фрагмента и возврата |

## Протокол наблюдений

Для каждого прогона фиксируются роль, сценарий, браузер, ширина экрана, способ ввода, время выполнения, число ошибок, запросы на помощь и результат. Отдельно записать, своими словами как участник различил подключение, запись, воспроизведение, пропуск и потерю связи.

| Роль и сценарий | Браузер и экран | Время | Ошибки и подсказки | Результат и наблюдения | Исправление и повтор |
| --- | --- | --- | --- | --- | --- |
| | | | | | |

Этап завершается после прохождения соответствующих задач представителями обеих ролей без подсказок. Ошибки, блокирующие задачу, исправляются с повторным прогоном. Результаты проверки браузером фиксируют техническую воспроизводимость.

## Проверка в браузерах

В Chromium и Firefox пройдены ввод камеры, восстановление после ошибки связи, воспроизведение и подтверждение записи, переход из тревоги и возврат фокуса. Проверены пропуск, оценочное время, повторная проверка каталога и сохранение позиции после обрыва. При ширине 1440, 768, 390 и 320 пикселей проверено отсутствие горизонтального переполнения. Автоматические проверки axe-core для обоих экранов прошли. Результаты прогонов с представителями ролей фиксируются в протоколе наблюдений.
