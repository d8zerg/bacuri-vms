# ADR-013. Порог покрытия продуктового кода

**Статус** - Принято.

**Контекст.** C++-сервисы работают в отдельных процессах, а JavaScript выполняется в браузере. Основные сценарии охватывают оба слоя. Для приёмки нужен измеримый нижний предел покрытия автоматическими тестами.

**Варианты.** Единый процент по репозиторию, независимые пороги для сервисов и клиента либо порог только для изменённых строк.

**Решение.** Требовать не менее 75% строк отдельно для продуктового C++ в `src/` и рабочего JavaScript в `web/`. GCC собирает данные в отдельном пресете по CTest и интеграционным прогонам. Chrome собирает данные V8 при прохождении сценариев рабочего клиента. Файлы тестов, макет, сгенерированные исходники и внешние библиотеки находятся за границами обоих измерений.

**Основания.** Независимые пороги выявляют пробелы в меньшем по размеру клиенте. Общий прогон учитывает код, который выполняется только при обращении к реальным сервисам. Покрытие строк показывает выполнение кода. Ожидаемый результат и отказы по каждому сценарию проверяются отдельными утверждениями тестов.

**Последствия.** Прогон требует отдельной инструментированной сборки и запуска браузера. Для разбора снижения покрытия сохраняются отчёты по файлам и непокрытым строкам. Код принудительно остановленного процесса может не успеть записать счётчики GCC.

**Проверка и пересмотр.** Шаг 0.3 включает `task coverage:check` в общий прогон. На шаге 4.2 гейт UI Kit переводит данные V8 по картам исходников в строки TypeScript. До интеграции экранов действует отдельный порог 75% для `web/client/src`, включая незагруженные продуктовые модули. Каталог и тестовые данные в знаменатель не входят. Оба браузерных отчёта проверяются через `task coverage:check`. При подключении рабочих маршрутов включить в измерение их прохождение через HTTPS. При появлении нового продуктового языка или смене инструмента заново проверить границы, учёт незагруженных файлов и сопоставимость результата.
