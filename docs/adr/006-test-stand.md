# ADR-006. Источники видео для воспроизводимой приёмки

**Статус** - Принято.

**Контекст.** Для проверки времени, повторов и разрывов нужен известный вход. Для демонстрации ввода камеры нужен RTSP-сервер самого устройства.

**Варианты.** Испытывать только на реальной камере, использовать только эмулятор или выполнять взаимодополняющие прогоны на одном Linux-стенде Docker Compose.

**Решение.** Управляемый источник подаёт два профиля с эталонными кадрами, пропусками и сдвигом часов. Отдельно на том же комплекте подключается физическая IP-камера, фиксируются модель, прошивка, настройки и декодирование записи и эфира в браузере.

**Основания.** Первый прогон позволяет повторить отказ и проверить точность кадра. Второй выявляет особенности согласования профилей, RTSP и времени конкретного устройства.

**Последствия.** Для итоговой приёмки требуется оборудование. Веб-камера за RTSP-эмулятором даёт дополнительный результат для тракта захвата. Вывод о поддержке IP-камеры относится к проверенному устройству и его прошивке.

**Проверка и пересмотр.** Для требований «Данные и доступ» и «Эксплуатация» приложить команды и эталоны синтетического прогона и отдельную строку физической камеры с результатами обоих маршрутов. Пересмотреть при расширении матрицы устройств или если стенд не воспроизводит наблюдаемый в эксплуатации отказ. Шаги 0.1, 0.3, 2.2 и 5.3.
