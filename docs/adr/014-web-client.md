# ADR-014. Архитектура единого веб-клиента

**Статус** - Принято.

**Контекст.** Монтажник и оператор работают на одной площадке без внешнего интернета. Сессии, права, каталог и лента принадлежат C++-сервисам. В браузере нужно совмещать навигацию с длительным воспроизведением и подпиской на тревоги. UI Kit должен показывать те же состояния на детерминированных данных и при работе с сервером.

**Варианты.** Отдельные страницы с общим CSS проще поставлять, но уже требуют согласовывать выбор точки и медиасеанс при переходах. React-фреймворк с серверным рендерингом полезен для выдачи готовых страниц сервером. Для двух авторизованных интерактивных маршрутов подходит и статическое приложение с клиентской маршрутизацией. [Варианты построения приложения React](https://react.dev/learn/build-a-react-app-from-scratch) · [Режимы React Router](https://reactrouter.com/start/modes)

**Решение.** Использовать React, строгий TypeScript, Vite и React Router в Data Mode. Vite собирает статические ресурсы, маршрутизатор управляет переходами и отменой загрузки. Площадка раздаёт ресурсы с того же HTTPS-источника, что и API. Node.js используется при сборке. Прямое открытие, обновление страницы и возврат браузером должны работать на поддерживаемых URL, включая переход из тревоги в архив. Версии зависимостей и Node.js закрепить при создании каркаса в lock-файле и образе сборки соответственно. [Статическая поставка Vite](https://vite.dev/guide/static-deploy) · [Отмена загрузок в React Router](https://reactrouter.com/explanation/race-conditions)

| Граница | Ответственность | Проверка |
| --- | --- | --- |
| UI Kit | Базовые элементы используют общие токены. Форма камеры, шкала, карточка тревоги и представление плеера получают типизированное состояние и сообщают о действиях. Базовые элементы не зависят от сценариев, транспорта или сессии | Правила импортов и изолированные примеры. Один и тот же компонент отображает пустое состояние, ожидание, результат и применимые отказы |
| Сценарии монтажника и оператора | Владеют выбранной точкой, интервалом, переходами и фокусом. Результат запроса или декодирования относится к конкретной точке и медиасеансу. События старого сеанса отбрасываются | Задержать ответ, сменить точку, затем доставить прежний ответ. Обновить ленту при открытом архиве и проверить возврат к исходной тревоге |
| Адаптеры и запуск | Общий адаптер сессии и типизированный REST-клиент используют [ADR-001](001-api-contracts.md). Адаптеры WebSocket, WebRTC и MSE владеют подписками, соединениями и ресурсами плеера. При запуске приложение связывает их со сценариями | В интеграции проверить повторную подписку по курсору, освобождение старого плеера, прекращение выдачи при отзыве прав и корректность следующего разрешённого сеанса |

**Основания и последствия.** Один набор компонентов обслуживает каталог и рабочие маршруты. Статическая поставка использует существующий сервер площадки. Команда отвечает за обработку прямых ссылок, очистку подписок и медиаресурсов. Отмена клиентского запроса сама по себе не отменяет уже применённую сервером команду. Повтор изменяющей операции следует контракту идемпотентности.

**Проверка и пересмотр.** На шаге 4.2 выполнить чистую production-сборку, проверку типов и импортов, пройти оба маршрута через штатный HTTPS-вход с отключённым выходом в интернет. Проверить прямую ссылку и обновление страницы с действительной и истёкшей сессиями. Зафиксировать размер начального JavaScript и CSS и время от навигации до доступности основного действия на стенде. Пересмотреть границы, если два маршрута дублируют состояние сессии или не укладываются в обоснованные пределы профиля.
