# Производительность запросов PostgreSQL

Для повторения выполните `task postgres:performance`. Команда создаёт отдельную базу, готовит исходную схему без проверяемых индексов, заполняет таблицы, собирает статистику и снимает планы. Затем устанавливает проверяемые индексы и повторяет те же операции с теми же данными. После проверки временная база удаляется.

## Рабочая нагрузка

На одной площадке созданы 20 000 источников карт, 20 000 заданий с разными состояниями, 500 планов и 20 000 размещений камер. Журнал содержит 20 000 тревог. У одной камеры есть 10 000 блоков записи и 10 000 частично перекрывающихся интервалов разрыва. Тест учитывает просроченные интервалы, ожидающие регистрации блоки, выбор конкретной привязки и запрос, превышающий одну страницу таймлайна.

## Результат контрольного прогона

## Изменения и границы измерения

- Два частичных индекса очереди карт содержат только ожидающие источники и задания, доступные обработчику. Приостановленные загрузки сохраняются в таблице. Отдельный индекс по `source_id` обслуживает поиск ссылок и каскадное удаление. Индекс по площадке, плану и точке обслуживает выборку маркеров.
- Поиск архива вычисляет границу хранения один раз на запрос. Для классификации отрезков он один раз читает интервалы, которые пересекают возвращаемую страницу. Сохраняются приоритет записи над разрывом, полуоткрытые границы, фильтр привязки и предел в 1 001 отрезок. Для определения границы страницы по-прежнему учитываются пересечения во всём запрошенном окне.
- Функция продвижения границы хранения выполняет один `INSERT ... ON CONFLICT`. Условие обновления сохраняет монотонность и исключает запись новой версии строки, когда граница уже дальше. Тест проверяет значение и физический идентификатор строки в этом случае.
- Представление тревог сразу возвращает состояние обработки. Снимок ленты и доставка изменений используют его без второго соединения с таблицей тревог. Существующие индексы по площадке, точке и позиции сохраняются. Время получения 100 тревог в этом профиле изменилось мало.

Измерения относятся к чтению на синтетически заполненной базе. Они не определяют число одновременно записываемых камер, задержки p95/p99 при конкурентной записи, сетевую задержку или загрузку дисков на конкретной площадке. Четыре новых индекса требуют места, а при изменении индексируемого состояния задания или размещения PostgreSQL обслуживает соответствующий индекс.
