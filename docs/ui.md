# Интерфейс и проверка пользовательских сценариев Bacuri VMS

**Статус визуальной системы** - Принято. Рабочий клиент запускается командой `task control:up`. После входа администратору доступен раздел «Камеры», оператору - «Мониторинг». [Рабочее место на локальном стенде](https://localhost:8443/) · [Настройка учётных записей](../README.md#сервер-управления)

Для воспроизведения отдельных состояний запустите `task ui-kit:up` и откройте раздел «Рабочее место / Экраны» в Storybook. Здесь те же компоненты используют фиксированные тревоги, локальные видеозаписи и имитацию отказа связи. Команда `task ui-kit:down` останавливает каталог. [Каталог компонентов](http://127.0.0.1:6010)

## Визуальная система

| Компонент | Правило |
| --- | --- |
| Рабочее пространство | Системная цветовая схема выбирает кремовые поверхности с молочными панелями или нейтральные серые поверхности и текст VS Code Dark+. Видеокадр и непрозрачные подложки надписей сохраняют цвета в обеих темах. На широком экране видео и тревоги находятся рядом, на узком лента следует после шкалы |
| Цвет и типографика | Обе темы используют [общие цветовые токены](../design/bacuri/tokens.css). В светлой теме заголовки и основной текст почти чёрные, подписи нейтрально-серые. Главная кнопка имеет приглушённую песочно-жёлтую заливку. Активный раздел отмечен фоном и нижней линией, выбранная тревога - фоном и боковой полосой. Оливковый - исправную связь и подтверждение, терракотовый - предупреждение, карминовый - тревогу или отказ. Время и счётчики используют моноширинные цифры |
| Фирменный знак | В шапке изображён поперечный срез бакури. Три кремовые дольки с семенами образуют треугольный просвет диафрагмы внутри золотого кольца. Для вкладки браузера у знака отдельная геометрия на 16 пикселях. [Комплект знака](../design/bacuri/brand) |
| Форма камеры | Явные подписи, раздельные адреса и подсказки по их назначению. Исправимая ошибка фокусирует поле, значения открытой формы сохраняются |
| Результат проверки | Связь, основной поток, дополнительный поток, запись и воспроизведение имеют отдельные состояния. Доступность камеры и успешное чтение кадра проверяются как разные действия |
| Шкала архива | Сплошная заливка для записи, диагональная штриховка для пропуска, вертикальные терракотовые штрихи для оценочного времени, точечная для каталогизации. Легенда, текст состояния и выделенная позиция дополняют цвет |
| Тревога | Карточка показывает состояние обработки, время UTC и точку. Общая подпись ленты сообщает об отсутствии приоритета в источнике. Открытие архива переводит фокус в область видео, возврат переводит фокус на выбранную карточку |
| Сбой | Сообщение показывает причину и доступное действие. Обрыв связи останавливает воспроизведение. После повторного подключения сохраняются выбранная тревога и интервал |
| Клавиатура | Tab и Shift+Tab перемещают фокус, Enter и Space активируют кнопки. На шкале клавиши со стрелками меняют позицию, Home и End выбирают границы. Видимый фокус обозначен обводкой |

После проверки потоков фокус переходит к созданию записи. По завершении записи он переходит к открытию фрагмента. После первого воспроизводимого кадра доступно подтверждение. Асинхронный шаг переводит фокус только если он оставался на исходной кнопке.

## Качество UI Kit и гипотезы для двух маршрутов

На шаге 4.2 у каждого компонента есть типизированные входные состояния, допустимые действия и ожидаемый результат для клавиатуры и дерева доступности. Например, для подтверждённого пропуска шкале нужны границы интервала, для оценочного времени - доступные сведения о погрешности. Оба экрана используют один контракт компонента. В ревью изменение общего состояния проверяют на обоих маршрутах, включая задержанный ответ после смены точки. Критерии композиции и контраста приведены ниже.

Изменение публичного свойства проверять в местах вызова на экранах. Новый визуальный вариант добавлять при наличии отличимого назначения в сценарии.

Для нового варианта взаимодействия зафиксировать ожидаемое улучшение относительно действующего интерфейса и признак ухудшения. На одинаковых данных сравнить число необходимых действий, повторный ввод и сохранение контекста. Вариант с потерей точки, ложным подтверждением или недоступным действием возвращают на доработку. Самостоятельность, время человека и понимание результата оцениваются на финальной серии по [заданиям первого использования](#проверка-первого-использования).

#### Шкала архива в UI Kit

Компонент получает окно и непересекающиеся интервалы в миллисекундах UTC, выбранную позицию и обработчики выбора и обновления. Владелец сценария передаёт непустое окно и позицию внутри него. Начало интервала включается, конец исключается. Пока позиция между известными интервалами, отображается «Нет сведений». Компонент сообщает выбранный момент вызывающему коду. Получение кадра и подтверждение записи принадлежат сценарию и плееру.

Сплошная полоса означает запись, диагональ - подтверждённый пропуск, вертикальные штрихи - оценочное время, точки - каталогизацию, горизонтальные штрихи - недоступный носитель или другой отказ выдачи. Текст рядом с курсором указывает причину пропуска или недоступности и границы. Для оценочного времени видна погрешность либо сообщение, что она неизвестна. При переходе через полночь видны обе календарные границы. Загрузка, пустой результат и ошибка каталога имеют отдельные примеры. При обновлении после ошибки фокус остаётся на кнопке, а результат объявляется через область статуса.

Локальный каталог запускается командой `task ui-kit:up` и доступен по адресу [http://127.0.0.1:6010](http://127.0.0.1:6010). Остановка - `task ui-kit:down`. Команда `task ui-kit:check` изолированно собирает библиотеку и каталог, проходит примеры в Chromium и Firefox в обеих темах и сохраняет результаты в каталоге отчёта. [Компонент](../web/client/src/ui-kit/ArchiveTimeline.tsx) · [Примеры состояний](../web/client/stories/ArchiveTimeline.stories.tsx) · [Браузерные проверки](../web/client/tests/archive-timeline.spec.mjs)

#### Форма подключения камеры в UI Kit

Администратор вводит название, адрес основного потока для архива и адрес дополнительного потока для эфира. Поля имеют постоянные подписи. Enter отправляет форму. При ошибке фокус получает первое ошибочное поле, а его доступное описание содержит назначение и текст исправления. Форма проверяет синтаксис RTSP и RTSPS. Адрес с реквизитами, строкой запроса или фрагментом отклоняется до отправки. Проверка доступности устройства, доверия сертификату и разрешений для открытого RTSP принадлежит серверу. [Контракт камеры](../contracts/v1/openapi.yaml) · [Политика транспорта](adr/012-camera-capabilities.md)

Форма получает текущие значения, состояние проверки и обработчики действий. Владелец сценария хранит черновик и допускает одну активную проверку. Редактирование сбрасывает прежний результат и отменяет запрос. Запоздалый ответ от отброшенной попытки игнорируется. При интеграции экран должен создавать отдельный экземпляр сценария по идентификатору выбранной точки. После обрыва оба адреса сохраняются для повтора. При частичном успехе каждый профиль показывает свой результат. Проверка записи и воспроизведения следует на экране администратора после проверки потоков.

Примеры используют детерминированные ответы без подключения к камере. Автотесты проверяют ввод с клавиатуры, повторную отправку, исправление адреса во время запроса, независимые результаты профилей, доступность и компоновку при ширине 320 пикселей и тексте 200%. [Форма](../web/client/src/ui-kit/CameraConnectionForm.tsx) · [Сценарий проверки](../web/client/src/workflows/useCameraConnectionCheck.ts) · [Примеры в Storybook](../web/client/stories/CameraConnectionForm.stories.tsx) · [Браузерные тесты](../web/client/tests/camera-connection.spec.mjs)

## Дизайн-ревью целых экранов

Автотесты проверяют экран ввода камеры и рабочее место оператора в контексте задания, а с этапа 7 также карту, план, обработку тревоги, ёмкость архива и экспорт. Для каждого сохраняют полные снимки при ширине 1440, 768, 390 и 320 CSS-пикселей, а для асинхронных переходов - последовательность состояний до ответа, после ответа и после повтора. Серия включает реальные длинные имена точек, время с часовым поясом, непустую ленту и диагностическую ошибку. Для каждой темы и ширины экран сверяют с сохранённым изображением рабочего клиента.

Параметры рабочего клиента - основной текст 1 rem с межстрочным интервалом 1,45, заголовок экрана от 1,65 до 2,25 rem, метаданные панели 0,875 rem. Форма и плеер используют одну шкалу отступов. Для изменения этих значений рецензент сравнивает перенос подписей, видимость действия и читаемость состояния на тех же полных экранах. [Стили рабочего места](../web/client/src/app/workspace.css)

| --- | --- |

На рабочем месте главный объект - видео выбранной точки, рядом различимы режим, время, шкала и выбранная тревога. На узком экране карточка и действия доступны по естественному порядку чтения. | Доступность | Из чистого входа пройти обе задачи клавиатурой в Chrome и Firefox. Измерить контраст обычного текста не менее 4,5:1, крупного - 3:1. Проверить сохранение подписей и действий при ширине 320 CSS-пикселей. | Пустые данные | Открыть площадку без камер, затем разрешённую точку без тревог | Текст называет пустой набор. Администратору доступно добавление камеры, оператору остаётся доступен эфир его точки |
| Ошибка и восстановление | Ввести неверный адрес, прервать связь, отозвать право во время просмотра | Для исправимого ввода фокус и сообщение относятся к полю, прочие данные формы сохраняются. При обрыве видны состояние и действие для восстановления. При отзыве выдача прекращается, запрещённые сведения исчезают |
| Неполный архив | Подготовить известный пропуск, неопределённое покрытие и эпизод с оценкой времени | Причина подтверждённого пропуска, неизвестность покрытия и погрешность времени различимы. Для точки с записью видны фактический кадр, позиция и режим «Архив» |

Браузерная автоматика фиксирует ревизию, полные снимки и различия с эталоном, контраст, дерево доступности и порядок фокуса при вводе с клавиатуры. Различие с эталоном требует исправления либо обоснованного обновления эталона с повторным прогоном. Рецензент оценивает визуальную иерархию по полученным экранам. Понятность сообщений, в том числе озвученных экранным диктором, проверяют в финальной серии 9.1. [Решение о дизайн-системе](adr/007-ui-states.md)

## Проверка первого использования

Пригласить администраторов с опытом подключения камер видеонаблюдения и дежурных операторов, впервые работающих с Bacuri. Выдать адрес входа, учётные данные, данные объекта и цель обычными словами. Пример для администратора - «Подключите камеру у ворот и покажите, как вы убедились, что запись можно посмотреть». Оператору - «Покажите, что произошло у ворот при сигнале, и вернитесь к наблюдению за тревогами». Наблюдатель сбрасывает данные и профиль браузера перед каждой попыткой, фиксирует действия, молчит и после завершения просит объяснить результат. Документация и показ порядка действий исключены из задания. Любая подсказка или вмешательство записываются как несамостоятельное завершение.

| Задание | Старт и граница замера | Успех и критическая ошибка | Предел и основание |
| --- | --- | --- | --- |
| Администратор, первая запись | От выдачи цели на экране входа. Камера доступна, точка ещё не заведена, известны адреса и параметры доступа. Человеческое время измеряется только в 9.1, включая вход и ожидание системы. [Численные пределы](../tests/cameras/qualification.json)

После успешного 8.3 на том же комплекте привлечь минимум пять новых администраторов и пять новых операторов. Обе группы охватывают оба целевых браузера. Первое задание выполняется при первом входе, затем участник проходит дополнительные задания своей роли и вариант отказа. Включить выполнение ключевого задания с клавиатурой и экранным диктором. ## Рабочие экраны

На площадке с локальной сессией администратор открывает `/cameras`, оператор - `/monitor`. В каталоге Storybook доступны те же компоненты с воспроизводимыми состояниями. Автоматический дизайн-гейт сравнивает полные экраны с эталонными снимками для каждого браузера и темы. Отдельные утверждения проверяют цвета, гарнитуру, размер заголовка и число колонок на каждой контрольной ширине.

| Действие | Результат и основание для отображения |
| --- | --- |
| Подключить камеру | Запрос имеет ключ идемпотентности, изменение ранее созданной камеры использует текущий ETag. Применённая версия должна совпадать с отправленной. Основной профиль подтверждает новый полный блок в манифесте, дополнительный - декодированный кадр WebRTC. Если проверка профиля не завершилась, он имеет состояние «Не подтверждён». |
| Проверить запись | Непрерывная запись уже работает. Кнопка ждёт полный блок, записанный после нажатия. Следующая кнопка открывает точный интервал блока через MSE. Подтверждение доступно после декодирования и снимается при потере доступа или изменении параметров. |
| Открыть тревогу | Одно действие по карточке открывает архив. Сервер задаёт точку, интервал и UTC. Наличие тревоги само по себе не подтверждает наличие видео. При каталогизации доступна повторная проверка, при пропуске видна причина. Общая подпись «Приоритет не задан» относится ко всем событиям ленты. |
| Вернуться в ленту | В URL остаются точка, границы интервала, UTC, идентификатор карточки и позиция прокрутки. Возврат переводит фокус на доступную карточку. Переход по сохранённому адресу повторно проверяет сессию и права. |

Оператор открывает архив одним нажатием на карточку. У администратора после ввода параметров четыре действия - подключить камеру, создать тестовую запись, открыть её и подтвердить кадр. Влияние на самостоятельность и время человека проверяется на этапе 9.1. [Протокол проверки](test-profile.md#приёмка-единого-веб-клиента)

## Карта региона и планы

Для отображения карты региона в веб-клиенте используется WebGL 2. В разделе «Карты и планы» администратор выбирает поверхность и существующую точку наблюдения, указывает место щелчком или вводит координаты с клавиатуры, затем нажимает «Сохранить положение». На карте используются долгота и широта WGS 84, на плане - доли ширины и высоты от левого верхнего угла. У одной точки может быть положение на карте и на нескольких планах.

В меню «Добавить план» задаются название и изображение PNG. Максимум для одного файла - 4 МиБ, 4096 пикселей по каждой стороне и 8 388 608 пикселей суммарно. Лимит изображений площадки - 16 МиБ. Сервер проверяет сигнатуру, размеры и декодирование изображения, отбрасывает вспомогательные блоки PNG. Изображения и координаты входят в резервную копию конфигурации.

Оператор видит планы, на которых размещена хотя бы одна доступная ему точка. Та же проверка действует для прямой ссылки на изображение. После выбора точки можно открыть эфир, архив или конкретную тревогу. Ссылка «Карты и планы» в навигации возвращает выбранную поверхность, положение и масштаб карты или прокрутку плана. Фокус возвращается на выбранную точку.

### Проверка события на карте

При подключённой ленте число возле камеры показывает новые тревоги этой точки в текущей ленте. На обзоре здания учитываются камеры его этажей. Выберите камеру и откройте «События камеры». Сверху показаны последние события по времени наблюдения, у каждой строки указаны время UTC и известное состояние обработки. «Показать ещё» раскрывает более ранние события из той же ленты.

Нажмите «Проверить», чтобы посмотреть запись на момент события прямо на карте. Переключатели «Архив» и «Эфир» позволяют сравнить запись с происходящим сейчас. Если запись ещё добавляется в каталог, панель дождётся её и откроет автоматически. При пропуске записи или неопределённом времени оператор увидит причину. Новые тревоги поступают в список, текущий просмотр продолжает показывать выбранное событие. «Открыть тревогу в мониторинге» ведёт к архиву и карточке обработки. При возврате сохраняются камера, план и выбранное событие, пока оно доступно в ленте.

### Привязка плана к геокарте

Откройте нужный план и нажмите «Привязать план к карте». Самостоятельный план можно использовать сразу после загрузки.

1. Выберите два ориентира, видимых на обоих изображениях, например противоположные углы здания. Отметьте A на плане и карте, затем B. По этим парам Bacuri определяет положение, масштаб и направление верха плана. Разнесите ориентиры как можно дальше.
2. Если известна реальная ширина всего изображения, выберите «Один ориентир и известная ширина». Укажите соответствующую точку, ширину в метрах и азимут направления вверх по изображению. Север соответствует 0°, восток - 90°. Ширина включает поля чертежа.
3. Для этажей одного здания укажите общее название здания. Нажмите «Предпросмотр» и меняйте непрозрачность. Проверьте совпадение ещё одного узнаваемого угла или входа. Если изображение растянуто или это схема без масштаба, используйте исходный чертёж с правильными пропорциями.
4. Для камер с существующей геопозицией мастер покажет расстояние до предложенного положения. Выберите источник отдельно для каждой точки и сохраните привязку. При работе без установленного региона доступны числовой ввод и расчёт. Для визуального совмещения установите локальную карту.

На обзоре территории нажмите название здания или выберите этаж в списке «План на геокарте». Смена этажа переключает изображение и набор камер. Из карточки камеры с вычисляемыми координатами можно открыть исходный план и переместить точку на нём. Направление её обзора на геокарте учитывает поворот плана и последнее доступное измерение PTZ. Обновление карт региона сохраняет привязку.

Чтобы вернуть самостоятельный план, откройте «Настроить привязку к карте», выберите «Снять привязку», проверьте действие и подтвердите его. Сохранённые ручные координаты камер снова доступны на геокарте.

### Камеры и секторы обзора

Администратор размещает точку на карте или плане, выбирает её и раскрывает «Настроить сектор обзора». Откройте эфир в соседней вкладке. Выберите заметный ориентир в центре кадра, нажмите «Указать ориентир на карте» и укажите его положение. Можно ввести направление вручную в градусах по часовой стрелке. На карте отсчёт идёт от географического севера, на плане - от верхнего края изображения.

Для фиксированной камеры введите горизонтальный угол обзора объектива. Для поворотной камеры остановите движение перед сохранением. При угловых координатах ONVIF показание связывается с ориентиром автоматически. Если камера возвращает условные координаты, укажите число градусов поворота на единицу pan для этой модели и установки. Его можно получить по двум ориентирам с известной угловой разницей. Для этого разделите изменение направления на изменение показания pan на участке без перехода через границу диапазона. Отрицательный знак соответствует обратному направлению оси.

Для PTZ используется основной ONVIF-профиль, выбранный при подключении. Приоритет имеет угол обзора, полученный от камеры. Для камер с нормализованным зумом можно задать углы на широком и длинном концах объектива. Между ними Bacuri показывает линейную оценку. При отсутствии данных зума используется заданный ориентировочный угол. Длина сектора на экране условна. Для помещения она не учитывает стены, а для уличной камеры - рельеф и дальность распознавания.

Оператор выбирает значок камеры и видит направление, угол и время последнего измерения PTZ. При потере связи сектор отображается пунктиром. При отсутствии абсолютной позиции или после замены устройства остаётся значок камеры. Для нового устройства повторите калибровку. Поворот с другого пульта или патруль обнаруживается при очередном опросе камеры. После команды из Bacuri опрос временно учащается.

### Установка и обновление регионов

Откройте «Карты и планы» под учётной записью администратора. Нажмите «Установить регионы». Выберите источник карт.

- **Из интернета.** Укажите адрес `https://.../catalog.json` и нажмите «Показать каталог». Адрес сохраняется для площадки. В списке видны название, объём и дата данных каждого региона.
- **Из файла.** Укажите ZIP на своём компьютере или носителе. Архив может содержать MBTiles во вложенных каталогах. Можно выбрать и одиночный MBTiles. Дождитесь загрузки файла в браузере и появления списка.

Отметьте нужные регионы или «Выбрать все», затем нажмите «Установить выбранные». Состояние каждого региона отображается отдельно. После постановки в очередь вкладку можно закрыть. При разрыве связи Core автоматически запрашивает оставшиеся байты с позиции, сохранённой на диске. Кнопка «Приостановить загрузку» ставит выбранный регион на паузу. «Продолжить загрузку» снимает паузу. Закрытие браузера и перезапуск Core сохраняют очередь, загруженные данные и установленную администратором паузу. Несколько установленных карт доступны оператору в списке «Регион».

Для обновления нажмите «Обновить установленные», затем «Проверить обновления» или «Обновить из файла». В списке появятся только установленные регионы, для которых источник содержит более свежие данные. При уменьшении покрытия интерфейс покажет число камер за новыми границами. Действующая версия доступна операторам до успешной установки новой, координаты точек сохраняются. Для региона с ошибкой доступно действие «Повторить».

### Подготовка и импорт региона

1. На машине подготовки получить региональную выгрузку OpenStreetMap в формате OSM PBF. Сохранить исходный файл вместе с пакетом поставки. [Выгрузки Geofabrik](https://download.geofabrik.de/)
2. Открыть слои выгрузки в ГИС, задать оформление и подписи. Например, в QGIS использовать алгоритм «Generate XYZ tiles (MBTiles)» с форматом PNG, размером тайла 256 пикселей, нужной областью и диапазоном масштабов. Импорт поддерживает пакеты до 8 ГиБ и уровни масштаба от 0 до 22. Результат экспорта - растровый MBTiles с координатами тайлов TMS и полем `bounds` в порядке запад, юг, восток, север. [Экспорт тайлов QGIS](https://docs.qgis.org/latest/en/docs/user_manual/processing_algs/qgis/rastertools.html)
3. На машине с Python и osmium-tool выполнить `python3 tools/map-metadata.py region.osm.pbf region.mbtiles "Название региона"`. Команда переносит время репликации из заголовка исходной выгрузки. При подготовке оформления соблюдаются условия лицензии исходных данных. [OpenStreetMap и ODbL](https://www.openstreetmap.org/copyright)
4. Для раздачи карт соберите каталог `python3 tools/map-catalog.py output north.mbtiles south.mbtiles --zip regions.zip`. Разместите содержимое `output` на HTTPS-сервере с поддержкой HTTP Range. Архив `regions.zip` можно передать на изолированную площадку. Файл индекса содержит сведения о регионах, размеры и SHA-256 пакетов. Издатель задаёт устойчивый идентификатор в поле метаданных MBTiles `region_id`. Для пакетов без этого поля идентификатором служит точное значение `name`. Сохраняйте идентификатор при выпуске обновлений. Один регион может занимать до 8 ГиБ, архив и сумма его распакованных регионов - до 32 ГиБ. [Генератор каталога](../tools/map-catalog.py)
5. Для импорта из локальной консоли после миграции базы выполнить `bacuri-vms-core import-map /import/region.mbtiles` с настройками подключения службы и `BACURI_SITE_ID`. Для стенда Compose команда приведена ниже.

```sh
docker compose run --rm --no-deps -T \
  -v "$PWD/region.mbtiles:/import/region.mbtiles:ro" \
  core /opt/bacuri/bacuri-vms-core import-map /import/region.mbtiles
```

Импорт проверяет пакет и публикует его одной транзакцией. При ошибке остаётся доступна предыдущая версия. При обновлении меняются идентификатор версии и адреса ресурсов, координаты камер хранятся отдельно. Регион восстанавливается повторным импортом сохранённого MBTiles.

### Контракт клиентов

`GET /api/v1/sites/{siteId}/maps` возвращает список установленных регионов, первый регион для совместимости с ранними клиентами, адрес стиля, планы, координаты разрешённых точек и локальные адреса шрифтов и значков. Отсутствующий регион обозначается `null`. Стиль версии 8 задаёт локальные XYZ-тайлы PNG. Надписи базовой карты уже включены в растровые тайлы. Веб-клиент и будущий клиент на Qt получают ресурсы с той же HTTPS-площадки с учётом сеанса. Изменение привязки выполняется через `PUT /api/v1/sites/{siteId}/maps/placement`, загрузка плана - через `POST /api/v1/sites/{siteId}/maps/plans`. Обе операции требуют роли администратора и CSRF-токена. [Контракт OpenAPI](../contracts/v1/openapi.yaml) · [ADR-017](adr/017-map-sources.md)

## Обработка тревоги и журнал

1. В мониторинге выберите тревогу. Рядом с архивным кадром откроется карточка с состоянием, ответственным и историей.
2. Нажмите «Взять в работу». Если двое дежурных нажали кнопку одновременно, карточка покажет того, кто первым принял тревогу на сервере.
3. Введите результат проверки и нажмите «Записать результат». Ответственный может уточнить результат до закрытия. Каждая сохранённая редакция видна в истории.
4. Введите основание и нажмите «Закрыть тревогу». Закрытая тревога остаётся в журнале. Если ответ потерян, «Повторить отправку» использует тот же ключ команды.
5. Откройте «Журнал тревог» в основной навигации или «Открыть журнал этой тревоги» из карточки. Поиск принимает идентификатор тревоги и часть текста результата или основания. Время указано в UTC. Из найденной записи можно вернуться к архиву.

В разделе «Поручения сервисам на этой точке» укажите имя сервиса, одно разрешённое действие и срок действия в минутах. Скопируйте показанный при выдаче токен и передайте его сервису по защищённому каналу. Команда сервиса выполняется от имени выдавшего поручение. Запись результата и закрытие доступны, когда он является ответственным. Чтобы прекратить доступ раньше указанного срока, нажмите «Отозвать». Карточка показывает действующие поручения текущего пользователя на выбранной точке.

## Экспорт фрагмента

В «Мониторинге» выберите точку и откройте архив либо перейдите в архив из тревоги. Разверните «Экспорт фрагмента», задайте начало и конец в UTC, нажмите «Подготовить комплект», затем «Сохранить комплект». Конец интервала исключён. При переходе из тревоги доступны запись её привязки и окно по 15 секунд с каждой стороны от момента тревоги.

Администратор предоставляет право уже имеющему доступ к точке пользователю. В командах `start_utc` и `end_utc` - границы разрешённого интервала UTC в формате RFC 3339 с суффиксом `Z`. Повторная выдача права заменяет прежние границы. Во время передачи ядро периодически проверяет текущие права, сеанс и срок хранения исходных блоков. Отзыв прерывает действующую передачу. Сохранённую получателем копию можно читать автономно. В журнале доступны пользователь, точка, границы, идентификатор комплекта, тревога при её выборе и результат запроса на выдачу.

```sh
docker compose exec -T core /opt/bacuri/bacuri-vms-core grant-export "$user" "$point" "$start_utc" "$end_utc"
docker compose exec -T core /opt/bacuri/bacuri-vms-core revoke-export "$user" "$point"
```

За один запрос можно получить до часа записи, до 256 исходных блоков и до 256 МиБ медиа. Целый блок сохраняется в исходном MP4. Для части блока ядро выбирает кадры по времени предъявления и повторно кодирует их в H.264. Каждый непрерывный участок представлен отдельным MP4. Описание содержит интервалы, причины известных пропусков, участки с неизвестным покрытием, идентификаторы точки, камеры, канала, профиля и блока, основание времени и контрольные суммы.

### Автономная проверка

Администратор заранее передаёт получателю открытый ключ площадки по доверенному каналу. Получите ключ командой

```sh
docker compose exec -T core /opt/bacuri/bacuri-vms-core export-public-key > trusted-key.json
```

На машине проверки нужны `tar` и `bacuri-vms-verify-export` из доверенной сборки для целевой системы. Распакуйте комплект без повышенных прав в новый пустой каталог. Перед просмотром проверьте комплект и сохраните проверенное описание.

```sh
mkdir episode
tar --no-same-owner --no-same-permissions -xf "$package" -C episode
bacuri-vms-verify-export trusted-key.json episode > verified.json
```

Код возврата 0 подтверждает подпись Ed25519, соответствие площадки доверенному ключу, состав файлов, SHA-256 каждого MP4 и разбиение выбранного интервала. Для автоматической сверки с заданием передайте ещё три аргумента `POINT_ID BEGIN_UTC_US END_UTC_US`. Несовпадение точки или любой границы завершает проверку с ошибкой. Откройте файлы `clip-*.mp4` в порядке, указанном в `periods`. Время в описании указано в микросекундах UTC от Unix epoch.

## Срок хранения архива

Администратор задаёт политику площадки командой `bacuri-vms-core set-retention DAYS [RESERVE_PERCENT]`. Срок задаётся целым числом суток от 1 до 36500. Резерв свободного места задаётся в процентах от 1 до 90, по умолчанию 20. На стенде Compose применяются 30 суток и резерв 20%.

```sh
docker compose exec -T core /opt/bacuri/bacuri-vms-core set-retention 30 20
docker compose exec -T recorder /opt/bacuri/bacuri-vms-recorder archive-status
```

При первом запуске и после обновления удаление по возрасту начинается с явной настройки срока. Сокращение срока сразу закрывает доступ к блокам, конец которых достиг новой границы. Увеличение срока действует на сохранившийся архив. Политика входит в резервную копию конфигурации.

Команда `archive-status` показывает применённые параметры и состояние тома. `available_bytes` - свободное место, доступное рекордеру, `reserve_bytes` - резерв. При остатке в пределах пяти процентных пунктов выше резерва появляется `low_space`. При исчерпании доступного для нового блока места появляется `recording_stopped`, рекордер фиксирует пропуск `storage_failure` и повторяет запись на следующем блоке. Переходы состояний попадают в журнал рекордера. При дефиците места освободите место вне действующих записей или расширьте том.

`capacity_depth_seconds` показывает, сколько секунд записи вмещает том при измеренном суммарном потоке. Расчёт учитывает место действующих медиафайлов и свободное место сверх резерва. `estimated_depth_seconds` ограничивает оценку заданным сроком, `remaining_seconds` показывает время до достижения резерва при текущей скорости записи без последующей очистки. Скорость измеряется по принятым данным за последние пять минут. Если в этом интервале нет данных для оценки, прогноз равен `null`. `cutoff_utc_us` и `removed_blocks` показывают последнюю подтверждённую границу и число блоков, удалённых за время существования локального журнала.
